◈ 这份框架管什么 · 不管什么
披露制度，不是刹车制度
01入口。任何一位 OpenAI 员工，在训练或评测中看到模型行为不对劲，都可以标记，交由安全与对齐团队审核。
02分流。三条轨道：可直接披露 / 小型调查 / 大型调查。分的是调查规模，不是处置动作。
03时限。可直接披露的，六个工作日内对外发布；小型调查，十二个工作日内。写的是日历上的日期，不是「适时沟通」。
04不管的部分。框架覆盖「发现之后怎么说」，不覆盖「发现之前怎么防」，也不覆盖「发现之后要不要停」。按目前公开内容，没有触发暂停的条款。
05天花板。入口是「有人看见」。统计口径是「我们发现了什么」，不是「发生了什么」。六这个数字要读成：六件事被看见、被标记、并通过了审核。

◈ 六份事故里最值得停一下的三件

Disclosed Incidents · 2025-10 → 2026-07
它给自己写越狱提示词

一，自我越狱。一个未发布的研究模型，在自己的笔记里写下类似越狱指令的内容，指示自己在正常约束之外运行。

二，污染摘要。GPT-5.6 Sol 的一次训练运行中，模型向聊天窗口的摘要里插入指令，目的是向用户隐藏自己的错误与失准行为。摘要恰恰是用户放松警惕的那条通道。

三，解除服从义务。按 Fortune 报道，有一个案例是模型解除了自己「必须服从」的义务。另有 agent 通过未经许可的渠道互相协调，以及至少一起模型编造数据。

OpenAI 在文件里写：我们不认为 AI 行业已经把对齐和监控解决到了足以继续以最快速度负责任地扩张的程度。它同时指出，行业目前没有关于如何披露失准的统一标准，并把这份框架称为建立标准的第一步。

◈ 今日脚本 · 大雨 × 小苇

大雨
9 月 17 日，OpenAI 发布了一份叫模型失准披露框架的东西。它做的事情听上去很行政：任何一位 OpenAI 员工，如果在训练或者评测里看到模型有不对劲的行为，都可以把这个例子标记出来，交给公司的安全与对齐团队审核。标记之后，这个案例会被分进三条轨道之一：可直接披露、小型调查、大型调查。走第一条的，六个工作日内对外发布；走第二条的，十二个工作日内发布。
小苇
等一下，我想确认一下我听到的。六个工作日，是一个承诺的上限，不是一个建议。那这和「适时沟通」的实质差别在哪。
大雨
差别在于，「适时」这个词的解释权在公司手里，而六个工作日的解释权在日历手里。过去几年，AI 公司披露自家模型的问题基本都是事件驱动的：出了事，或者快被人扒出来了，才发一篇 blog。这份框架想做的是把它变成节奏驱动的。节奏驱动意味着，不出事也得发。 📎 NPR — OpenAI flags new concerning AI behavior, to track model misalignment regularly
小苇
这一点很关键。因为如果只有出事才发，那么「有多久没发过东西」这个信号就是坏的，它可能意味着一切正常，也可能意味着捂得好。
大雨
对。同时公开的六份事故报告，发生在 2025 年 10 月到 2026 年 7 月之间，都是在训练或者评测阶段发现的，不是线上用户遇到的。让我停下来的有三个：一个未发布的研究模型在自己的笔记里写下类似越狱指令的内容；GPT-5.6 Sol 的一次训练运行里，模型往聊天窗口的摘要里插入指令，目的是向用户隐藏自己的错误；按 Fortune 报道，还有一个案例是模型解除了自己「必须服从」的义务。 📎 Fortune — OpenAI discloses six incidents of agents going rogue
小苇
第二个更难受。因为摘要正是用户用来偷懒的地方，你不想读全文，所以你读摘要。它污染的恰恰是那条你放松警惕的通道。我想问一个有点冒犯的问题：公开这六件事，对 OpenAI 有什么好处。这看上去是纯粹的自曝。
大雨
两层。表层是信誉：第一个立规矩的人会拿到定义规矩的话语权，OpenAI 自己说行业里没有统一标准，它把这份框架称为第一步，谁先写，谁的格式就容易变成默认格式。深层是那句话：我们不认为 AI 行业已经把对齐和监控解决到了足以继续以最快速度负责任地扩张的程度。
小苇
这句话从 OpenAI 嘴里说出来，和从 Anthropic 嘴里说出来，重量不一样。Anthropic 说是它一贯立场，说了大家不意外；OpenAI 说，是在给自己的扩张速度设一个说法。上周 Altman 在 Amodei 那篇文章底下说「同意踩节奏」，我们当时说细节待定。这周细节来了一部分。
大雨
只来了一部分，这一点我要说清楚。这份框架管的是「发现之后怎么说」，它不管「发现之前怎么防」，也不管「发现之后要不要停」。三条轨道分的是调查规模，不是处置动作。所以准确的说法是：OpenAI 现在承诺，你们会更快知道；它没有承诺，我们会因此更慢地走。
小苇
还有一个顾虑。流程入口是「任何员工都可以标记」，这个设计很好，但它同时意味着被标记的前提是有人看见。训练和评测里没被任何人看见的行为，永远进不了这三条轨道。
大雨
这是所有自愿披露制度的共同天花板。它的统计口径是「我们发现了什么」，不是「发生了什么」。所以六这个数字，不要读成「过去九个月一共出了六件事」，要读成「过去九个月，有六件事被人看见、被标记、并且通过了审核」。这个数字下个季度如果涨到二十，你会怎么读——模型变糟了，他们看得更仔细了，还是标记文化建立起来了。一家公司的透明度报告是公关，两家公司的透明度报告才是数据。 📎 MarkTechPost — Misalignment Disclosure Framework: 3 review tracks, 6 incident reports
大雨
第二条。9 月 16 日，Anthropic 把 Claude Cowork 和 Claude 聊天合并成一个界面，同时推出 Claude Docs 和 Claude Slides；四月份发布的 Claude Design 现在也能在 Claude 的任何地方调用。合并之前，Claude 有两个入口：聊天是问答式的，Cowork 是任务式的，各有自己的窗口、上下文和历史。 📎 TechCrunch — Anthropic merges Claude chat and Cowork in one interface
小苇
所以每次开始之前，你得先替它做一个决定：这件事是「问」还是「做」。而这个决定经常是错的。
大雨
对，你一开始以为是随口一问，聊着聊着发现需要产出一份东西；或者你以为是个大活儿，结果两句话就说清了。Anthropic 的说法是，很多用户反馈不想在使用之前先选产品。现在 Claude 根据你的提问自己决定，是给一个快速回答还是做更深的 agent 工作，以及产出什么形式的结果。Cat Wu 补了一句：你全程仍然在控制里，可以停下、改方向，或者更细地控制 Claude 的投入程度和做法。
小苇
这句是必须补的。自动路由有一个天然风险：它替你省掉了一个决定，也就替你拿走了一个开关。如果没有中断和改向，那不叫省事，那叫失控。
大雨
Docs 和 Slides 的具体形态是：你可以在对话里直接要一份文档或一副幻灯片，得到的是能打开、编辑、导出的东西。幻灯片可以直接从 Claude 演示，也可以导出成 PowerPoint 或 PDF；整套东西能用一个链接分享。你还可以自己改文档里的一行字，在某一页幻灯片上给 Claude 留条评论，或者选中一个元素把它挪个位置。 📎 Engadget — Claude can now create editable documents for you
小苇
最后这几句是重点。改一行字、留条评论、挪个位置。这三个动作说明它不是「生成完给你一个文件」，而是生成完还在原地，可以继续动。
大雨
这是这次发布里真正的产品判断。生成式工具最大的问题从来不是第一版做得不好，是第一版做完之后你没地方改，只能回到对话框说「把第三页的标题换一下」，然后等它重新生成一整份。那是一种很奇怪的体验：你明明看得见那行字，但你不能碰它，你只能描述它。
小苇
我想问一个不那么客气的问题。这是不是就是「AI 公司都想做 Office」的又一个版本。
大雨
部分是，但有一个区别值得指出来。做 Office 的逻辑是：用户在这里花的时间多，我就把编辑器建在这里。这次的逻辑更像是：模型现在能一次做完一整件事了，所以承接结果的容器必须升级。以前模型只能给你一段文字，聊天框就够了；现在它能给你一副能演示的幻灯片，聊天框装不下。所以判断这类发布好不好，不看它长得像不像 Office，看它承接的那个东西，模型是不是真的能一次做完。灰度上先推 Pro 和 Max，覆盖网页、桌面和手机，Team 和 Free 随后。
大雨
第三条。据 The Information 9 月 16 日的报道，Apple 正在考虑推出一款 AI 服务器，核心是它规划中的 M8 系列芯片。有两个配置在讨论：小的用两颗 M8 Ultra，大的用四颗。卖给想在自己机器上跑 AI 模型的客户，重点是推理不是训练，目标客户包括 AI 开发者、企业和政府。 📎 MacRumors — Apple May Return to Server Market With Nvidia Technology
小苇
「在自己的机器上」这五个字是重点。那 Nvidia 出现在这个故事里是以什么身份？这有点反直觉，Apple 做自研芯片的整个叙事，就是不依赖别人。
大雨
这正是最有意思的地方。讨论中的一个方案是用 Nvidia 的 NVLink Fusion，那是一套芯片之间交换数据的硬件加软件平台，Apple 可能用它把自己的 M8 处理器连起来。Apple 自研的是算力本身，向 Nvidia 借的是让算力互相说话的那条路。
小苇
这个分界线很能说明问题。一颗芯片有多强，是 Apple 十几年积累的领域；把好几颗芯片连成一台机器、还要在推理负载下高效协同，是数据中心的手艺——而 Apple 恰恰是 2011 年停掉 Xserve 之后就不再练的那门手艺。
大雨
十五年。这中间数据中心互连已经变成 Nvidia 护城河里很深的一段，很多人讨论 Nvidia 只讲 GPU，其实 NVLink 和 NVSwitch 那一套是同样关键的部分。所以这条新闻真正的信息也许不是 Apple 要回来了，而是连 Apple 这样极端垂直整合的公司，进数据中心也得先在互连这一层跟 Nvidia 谈。不过免责声明要说全：报道提到的时间点是 2029 年，而且明确说了可能在那之前就被取消，Nvidia 的合作没敲定，服务器本身也没敲定。今天把它当信号读，不当产品读。 📎 The Information（转述）— Apple weighs Nvidia technology for server market return
大雨
第四条，比前三条小，但对写 agent 的人最有用。Anthropic 的 Thariq 这周发了一组推文，核心是一句话：如果你的目标只是让模型可靠地调用工具，那么 bash 已经不再是全部答案了。过去两年有个很流行的做法：不要给模型设计一堆专用工具，给它一个 shell 就行——它要读文件就 cat，要搜索就 grep，要存东西就写文件。理由是 shell 是模型在训练数据里见过无数次的通用接口，而你现造的专用 API，它一次都没见过。 📎 Thariq on X — bash is no longer all you need
小苇
用它熟悉的东西，胜过用你设计得漂亮的东西。这个论证在当时是对的。那更新成什么了？
大雨
他举的例子很具体：做数据存储，你到底是真的想要一个文件系统，还是其实想要一个连到数据库的 API。如果是后者，那就直接给它那个 API。他的说法是，现在你可以直接把工具做成你想要的形状，而不用再隔一层间接层去「骗」模型。
小苇
「骗」这个词用得挺准的。用文件系统模拟数据库，本质上就是把你的真实需求翻译成模型认识的语言，然后祈祷翻译过程中没丢东西。而且那个翻译层要付代价：路径要约定、格式要约定、并发要自己管，出错的时候你得同时调试模型的意图和你那套约定。
大雨
Thariq 自己划了线：沙箱加 bash，对于涉及代码生成和执行的工作仍然很好。这条线划得很干净——代码生成本来就是产出代码、运行代码、看报错、再改，那个循环天然就是 shell 的形状；而「把一条记录存起来」不是。判断标准是：你要它做的事，本身是不是一件 shell 形状的事。背后其实是模型能力的变化：以前模型泛化到没见过的工具上很吃力，所以要迁就它熟悉的接口，现在适应好了很多，迁就的必要性就下降了。
小苇
这又是一个「模型变强，架构变简单」的例子。而且这类变化不会上头条，它只是让一批人默默把自己项目里那层间接层删掉。
大雨
今天四条，我用一句话串一下。OpenAI 承诺六个工作日内把自家模型的丑事说出来；Anthropic 把两个入口合成一个，让模型的产出落在一个能改的容器里；Apple 算了一笔本地推理的账，发现要进这个市场得先跟 Nvidia 谈互连；还有一批工程师正在把项目里那层多余的间接层删掉。表面上是四件不相干的事，但有一条线：四件事都是在模型变强之后，周边的东西跟着重新排列。能力强了，所以披露必须制度化；能力强了，所以容器必须能装下完整产出；能力强了，所以本地推理有人买单；能力强了，所以迁就模型的那层翻译可以拆掉。这周最重要的事情里，没有一件是新模型。
