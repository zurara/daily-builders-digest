🎙 今日播报 · 大雨 × 小苇
开场
大雨
欢迎来到 Daily Builders Digest，今天是二〇二六年十一月四号，星期三，产品日。我是大雨。
小苇
我是小苇。上周我们聊的是 agent 开始用电脑以后，人管什么。这周呢？
大雨
这周四条。第一条，OpenAI 公开了自己重写的 Git 后端，叫 Pando，原因是 Codex 产生的提交太多，原来的系统扛不住。第二条，ChatGPT 的 Dots 以后会自己选模型，一个任务里不同部分可以用不同模型。第三条，苹果开始测试 Apple Watch 的两个「一直在听」的功能：Live Rewind 和 Siri Recap。第四条，App Store 从十一月十六号起，要求开发者申报 app 里有没有和 AI 伴侣的恋爱或性内容，有的话最低 18 岁以上。
小苇
这四条差别挺大的。
大雨
我把它们放在一起，是因为每一条都在改一个默认值。Pando 改的是 Git 里「所有人看到同一个时间点」这个默认。Dots 改的是「用户自己选模型」这个默认。手表改的是「旁边的人知不知道自己被录」。App Store 改的是「AI 聊天 app 默认几岁能用」。我想问的是：这些默认值是谁定的，被影响的人有没有机会说话。
一 · OpenAI Pando：agent 把 Git 挤爆了
大雨
先说事实。十一月二号，OpenAI 发了一篇工程文章，标题是《Scaling Git at OpenAI》。他们给公司的大仓库换了一个新的 Git 后端，叫 Pando。工程师和 Codex 照样用普通的 git push、git fetch，变的是服务器那一侧。
📎 来源: OpenAI Rebuilt Git After Codex Load Sent Monorepo Reliability Below 90% — Qodo（引用 OpenAI 原文）
小苇
为什么要换？
大雨
因为 Codex 让每个工程师可以同时开很多任务，每个任务都是新的分支、新的推送、新的合并，每次推送还会触发好几个 CI 任务去拉同一个提交。从二〇二五年底开始，这个大仓库的相关系统可靠性有时候掉到 90% 以下：拉取慢、推送慢、合并失败。
小苇
换完效果呢？
大雨
OpenAI 自己报的数字：推送的中位延迟降了将近 80%，每天给客户端发将近 1 PB 的 Git 数据，高峰一小时超过 57 TB，99% 以上走本地缓存。Pando 从今年四月开始承接生产流量，用 Codex 做的，大约十周上线：一个工程师设计核心，几组 agent 写实现。这些都是 OpenAI 自己报的，没有公开代码。
小苇
技术上改了什么？
大雨
最关键的一个取舍：原来的系统保证整个仓库所有分支是同一个时间点，所以推不同分支的人也要排队。Pando 放弃了这个保证，每个分支各管各的。你读一个分支，拿到的就是写这个分支的人当时的历史。但你同时读几个分支，就不能假设它们是同一个时刻的。OpenAI 的判断是：人和 agent 在意的是单个分支里的先后，不在意全局顺序。
小苇
这对不在 OpenAI 的人有什么意义？
大雨
两点。第一，agent 的使用量会先压垮你的工具链，然后才轮到你的产品。OpenAI 是第一个公开说「Git 服务被我们自己的 agent 打挂了」的公司。第二，Qodo 那篇文章说得对：推送不再失败以后，所有分支都会涌到代码评审。GitHub 的数据是，今年九月超过 40% 的 PR 第一版是 agent 写的，三月是 17%。所以下一个瓶颈是人读不过来。
小苇
Thibault Sottiaux 那条推文就是说这个吧。
大雨
对，他说「我们懂一点 Git 功夫」，两千三百多赞。Greg Brockman 说在考虑对外提供，但现在还没有。
二 · ChatGPT Dots：模型由它自己选
大雨
第二条。先说 Dots 是什么。九月二十九号 OpenAI 发了 Dots，是一种在对话之外持续工作的 agent，每个 Dot 跑在自己的云端电脑上，做完把结果拿回来给你看。它会记住你在做的事，比如你在计划旅行，它会一直记着预算、目的地和日期。目前给 Pro 和 Business Premium 的成年用户逐步开放。
📎 来源: ChatGPT Dots will pick their own AI model for each task — Tbreak
小苇
这次变了什么？
大雨
十一月二号，Thibault Sottiaux 发推说：「你的 Dot 会为任务选择最合适的模型，不同部分可以用不同的模型。」可选的模型里加了 GPT-6.1 Terra，原来只有 GPT-6 Astra。Terra 更快、更便宜，OpenAI 说这能让 Dots 开放给更多人。
📎 来源: Tibo on X: "Your dot will choose the best model for the task…"
小苇
用户还能自己选吗？
大雨
不知道。报道里写得很清楚：OpenAI 没说 Dot 怎么决定用哪个模型，没说能不能手动改，没说什么时候上线、哪些套餐有。
小苇
那这是好事还是坏事？
大雨
对大多数人是好事。大多数人不想知道 Astra 和 Terra 的区别，他们只想把事做完。但对做产品的人有两个问题。第一，同一个任务今天用这个模型、明天用那个模型，结果可能不一样，用户会觉得「它今天变笨了」，但说不出原因。第二，选模型其实是在选成本。路由逻辑既服务用户，也服务 OpenAI 的毛利。用户看不到路由，就没法判断它是在帮自己省事还是帮公司省钱。
小苇
那要怎么做才算好？
大雨
我觉得最低限度是：事后能看到用了哪个模型。不需要每次让用户选，但出了问题要能查。今天播客那一期也讲到这个，后面再说。
三 · Apple Watch：Live Rewind 和 Siri Recap 进入测试
大雨
第三条。十一月三号，苹果发了 iOS 27.3 和 watchOS 27.3 的第一个开发者测试版，里面有两个功能，九月发布 Apple Watch Series 12 时公布过，统称 Audio Intelligence。
📎 来源: Apple Begins Testing Its Controversial Always-Listening AI Feature — Gizmodo
小苇
具体是什么？
大雨
第一个叫 Live Rewind：双击数码表冠，可以拿到手表附近刚才 15 秒对话的文字稿。第二个叫 Siri Recap：在一天里持续听你的对话，生成摘要和要点。两个都要手动打开。Live Rewind 拿到的片段，不存到 Siri 应用里的话，30 秒后删除。Siri Recap 的摘要可以存到 iPhone 的备忘录，不存的话七天内删除。欧盟暂时不提供。正式版计划十二月。
小苇
15 秒，听起来不多。
大雨
问题不在长度，在于对话里另一个人。戴表的人打开了这个功能，坐在对面的人没有打开任何东西。彭博九月就报道过，在美国一些要求双方同意录音的州，这可能有法律风险。苹果的做法是：激活 Live Rewind 时有一声提示音，屏幕上有动画，摘要里去掉能识别个人的信息。
小苇
提示音够吗？
大雨
我觉得不够，但这不是苹果一家的问题。Meta 眼镜录像时有指示灯，后来有人想办法挡住了。提示音和指示灯是在告诉旁边的人，它们不是在征求同意。这件事的产品难点是：被影响的人不是你的用户，不在你的设置页面里，你没有地方问他们。
小苇
那做产品的人能做什么？
大雨
苹果做对的有两件：默认关闭，默认很快删除。30 秒和 7 天这两个数字是认真定过的。还能多做的一件：让「被录的人」也有一个反应方式，比如对方说一句话就能让这段不被保存。现在没有。
四 · App Store：AI 伴侣 app 要申报，最低 18+
大雨
第四条，也是十一月三号。苹果发开发者通知：从十一月十六号起，开发者要申报 app 里有没有两类功能。一类是真人之间、或者人和 AI 伴侣之间的恋爱或性内容，有的话最低年龄评级 18+。另一类是真实位置共享，这一类不一定直接加年龄限制，看当地法规，比如巴西要求 16+。所有 app 最晚要在二〇二七年一月十二号前申报完。
📎 来源: Apple to Place Stricter Age Restrictions on Dating Apps and Some AI Chatbots — Gizmodo
小苇
18+ 就能挡住未成年人吗？
大雨
挡不住全部。年龄评级本身不会直接封锁，它的作用是让家长用「询问购买」和「屏幕使用时间」去限制。所以这条规则真正改的是：家长不用自己去判断某个聊天 app 有没有恋爱模式，评级会替他们标出来。
小苇
那对通用聊天产品呢？比如 ChatGPT、Grok 这种，不是专门做伴侣的。
大雨
这就是麻烦的地方。苹果的定义是「与用户进行性或恋爱内容的虚拟伴侣」。Grok 有一个「spicy」模式。OpenAI 原来在做成人模式，今年三月说推迟了。通用产品如果有这类模式，就得选：要么整个 app 变成 18+，要么把这个模式拆出去，要么关掉。
小苇
这又回到默认值了。
大雨
对。以前是开发者自己决定写不写、写多少。现在苹果把问题写进了上架流程，每个开发者都得回答一次。我觉得对做 AI 产品的人来说，十一月十六号之前要回答清楚一件事：你的产品在什么条件下会进入恋爱或性内容，这个条件是用户打开的，还是模型自己滑过去的。后一种最难申报。
关注建造者
小苇
最后是关注建造者。
大雨
今天挑四条。第一条是 Thariq，以前在 Anthropic 做 Claude Code，六千七百多赞：「用了一周，我的结论是做好工作不需要无限 token，两百美元的套餐就很好。而且这是智能最贵的时候了。」
小苇
这跟 Dots 那条能对上。价格往下走，路由就是在决定省多少。
大雨
对。第二条是 Thibault Sottiaux 讲 Pando 的，两千三百多赞，前面说过。第三条是 Guillermo Rauch，两百三十赞：「无状态沙盒是错的衡量标准。agent 只有带着自己的工作环境才有用：身份、技能、代码库、记忆。」
小苇
这条跟 Dots 也有关系，每个 Dot 跑在自己的云端电脑上，带着记忆。
大雨
是。第四条是 Peter Yang，两百赞。他让 ChatGPT 和 Gemini 都给一篇文章提修改意见，ChatGPT 的几乎都不好，Gemini 的很好。但 Gemini 的工具 Antigravity 不能操作浏览器，他只好把 Gemini 的意见粘回 ChatGPT，让 ChatGPT 去改。他的原话是：最好的写作模型被它的外壳拖住了。
小苇
这正好说明为什么要自动选模型。用户自己在手动做路由。
大雨
对，而且手动路由很累。
大雨
播客是 Latent Space 十一月二号那一期，嘉宾是法律 AI 公司 Legora 的 CTO Jacob Lauritzen，标题是「看不到数据的时候怎么做法律 agent」。
📎 来源: Latent Space · Building Legal Agents When You Can't See the Data — Jacob Lauritzen, CTO of Legora
小苇
看不到数据是什么意思？
大雨
律所的数据大多是他们客户的，高度保密，Legora 不能看。所以他们有一个专门做评测的团队，去猜律师在做什么，自己搭评测集。比如造一个一万个文件的尽调数据室，规定一份好的报告要包含哪些风险点。他们不用真实数据改写，因为光去掉名字可能不够安全，他们选最保守的做法，只把失败归到十几二十种已知类型里。
小苇
这跟模型路由有什么关系？
大雨
他说他们做了一张热力图，追踪每个模型在每个法律领域、每类任务上的表现。很多次模型更新是有的变好、有的变差，比你想的多。所以他们按任务选模型，有的用开源模型，有的自己后训练，有的用最强的模型，还要考虑成本、延迟、数据合规和地区。他叫这个「模型套利」。
小苇
那就是 Dots 在做的事，只是 Legora 自己能看到热力图。
大雨
对。差别就在这儿：Legora 的路由，团队自己能看到、能解释。Dots 的路由，用户现在看不到。
结尾
小苇
今天的问题留给大家：你的产品里，哪个默认值是你替用户定的，用户自己知道吗？
大雨
我们下周三见。今天是十一月四号，这里是每日快报。
