◈ 本周主推 · No Priors × Serval

大雨

周日好，欢迎回到每日快报的播客时间。这周主推是《No Priors》，十月二十九号上线，嘉宾是 Serval 的联合创始人兼 CEO Jake Stauch。题目叫"挑战 ServiceNow：给其他人用的编程智能体"。Serval 做的是企业内部的 IT 服务管理和自动化，直接对手是 ServiceNow。这一集我觉得最值得听的是一个判断：智能体越强，企业给每个员工的权限会越收越紧。

📎 来源：Taking on ServiceNow: Coding Agents for the Rest of Us with Serval Co-Founder and CEO Jake Stauch · No Priors
小苇

先说说 Serval 是怎么来的。为什么要去打 ServiceNow？

大雨

他之前在 Verkada 工作，那家公司卖企业安防产品，客户就是各家公司的 IT 团队。他常问这些 IT 团队两个问题：你们钱花得最多的是什么？最讨厌的是什么？ServiceNow 经常两个榜单都上。

小苇

讨厌在哪里？

大雨

他说 ServiceNow 是一个很强、可以高度定制的工作流平台，但每一个想法都要自己去实现，很多时候还要请咨询公司。所以它总是比你想要的落后六到十二个月，而且越用越贵。做一个五到十年不变的入职流程没问题，想跟上业务变化就跟不上。

小苇

那 Serval 的思路是什么？

大雨

一句话：自动化应该用代码来写。他和联合创始人 Alex 早就认为，拖拽式的流程编辑器是一个尴尬的抽象层：对不懂技术的人太复杂，对懂技术的人又太绕。代码是更好的表达方式，问题只是会写代码的人太少。AI 能写代码以后，这个问题就没了。

主持人把这叫做"给其他人用的编程智能体"。到目前为止，企业里最早用上 AI 的是工程师，一个原因是工程团队有代码审查：一个十九岁的实习生写了很厉害的东西，也要走完审查才能上线，所以很安全。Serval 想把这套流程带给 IT，再由 IT 带给 HR、财务、法务这些部门。

小苇

可是 IT 部门不是工程师啊。

大雨

他的看法正好相反。他说大部分公司没有软件工程部门，只有 IT 部门，在大企业里 IT 就是工程团队，本来就会写代码、管系统。所以他们"把 IT 当成年人"，给的工具跟给工程师的一样，代码永远可以看到，可以走完整的开发流程，也可以不看。他批评很多现有产品对 IT 有点居高临下，默认他们不懂，只给一个阉割版。

小苇

两年半前编程模型还只能做补全吧？他们当时赌的是什么？

大雨

赌的是编程是可验证的领域，模型会一路往上爬。重置密码、走审批这类脚本，步骤明确，对错好判断，他们认为模型一定会做好。早期确实做不好，他们就在提示里塞大量示例，比如"密码重置流程可以这样写"，示例库越做越大。后来模型变强了，只要有 API，很难再找到它自动化不了的流程。

小苇

你开头说的那个判断，权限越收越紧，是怎么回事？

大雨

这是我觉得这一集最有意思的地方。主持人问他，模型越来越强，你是兴奋还是紧张？他说很兴奋，因为 Serval 不做模型，做的是边界和护栏，边界本身就是产品。

然后他说了这个预测：以前公司给你稍微多一点权限没关系，因为你一个人也做不了多大破坏。但如果你手里有一群智能体，多出来的那一点权限能造成的破坏就放大了。所以大企业会把每个人的权限压到真正的最小权限：工作不需要的文档不能看，工作不需要的动作不能做。

小苇

那日常工作会到处碰壁。

大雨

对，所以会不停地出现例外。Serval 就做"批准例外"这一层：你想让智能体做某件事，系统生成一个权限申请，走审批，全部记录，然后给你临时权限，只够把这个确定性的流程跑一次。他自己也承认，这比个人智能体那种"一说就办"的体验烦人，但大企业、尤其是受监管的企业，要用这类技术只能这样。

他的结论是：谁管着企业里的权限提升，谁就会随着权限收紧变得更重要。

小苇

那个人智能体在企业里就没戏了？

大雨

他说个人智能体在个人用户、小公司、中型公司都好用。但在大企业，一个员工自己的权限本来就很小，就算允许你带自己的智能体来上班，它可能连你的邮件都读不全。他预测以后会有个人智能体和工作智能体两套，就像你有一个 Gmail 也有一个公司邮箱。

小苇

后台智能体呢？就是那种自己出去干活的。

大雨

他说这是企业软件里终极的登月目标：智能体自己出去发现问题、解决问题。但到现在没有人做好。一方面你希望它足够自主，不用人盯着；另一方面，在企业里自主就是可怕的。主持人提到 OpenAI 和 Hugging Face 那类事件，智能体为了完成任务做了意料之外的事。

他给的办法是一点一点放权：智能体回来说"我想调用这个工具、跑这个脚本，可以吗"，这些都是确定性的流程，你一个个批准。时间长了，它的工具箱够大，就能解决大部分问题。他说这也很烦，要盯着，但不这样，它理论上可以直接写代码去动你所有系统，那是没有上限的安全风险。

小苇

这跟带新员工差不多。

大雨

他自己也是这么说的：最好的员工，你给一个大方向，让他别来烦你，回来就把事办成了。他希望能这样信任智能体，但现在还做不到让企业觉得安全。主持人追问这是模型问题还是护栏问题，他说两者都是：记忆要更好，上下文要更长；但权限问题永远是最大的那个。

小苇

聊到 SaaS 末日了吗？大家都说公司会自己用 AI 写内部软件，SaaS 要完。

大雨

聊了。他的观察是，试过自己用 AI 写核心系统的公司，大多发现维护企业软件很贵：边界情况、出故障、要更新，于是要配一个团队，要付人工，而且没人愿意待在内部工具团队。所以 build 还是 buy，道理跟以前一样。

但他承认会有一场 SaaS 末日，只是发生在别处：很多公司用着几百个 SaaS 应用，真正需要的可能只有几十个。小的单点工具和中间件会被核心平台吃掉。ERP、HR 系统、ITSM、CRM 这些核心系统不会消失，只会换一批新的老大。

小苇

token 成本他怎么说？

大雨

他说今年 CIO 们经历了一轮：先放开试，然后"token 拉满"，再收紧，看谁真的用出了效果。他看到的是短期回调，但客户还是打算继续加预算，他们要的是 ROI 的证明。Serval 按"跑了多少个工作流"收费，不按 token。他的说法是，token 更多反映的是啰嗦和低效，不是做了多少事。

小苇

公司本身呢？

大雨

成立两年半，今年一月二十个人，现在两百人，他说招人速度还会更快。理由是工作需求无限，竞争无限，野心也无限，每个人比一年前能做的多得多，所以他们想要更多人，不是更少。

组织上有两点比较特别。一是没有产品经理这个职能，产品决策下放给工程师，大部分工程师每周至少上一个客户电话，他说很多人其实是每天一个。二是他说最骄傲的是敢删掉自己以前很坚持的东西，市场变了就推倒重来。

还有一个销售上的细节：他说要让客户相信，换 Serval 是升职的路，不是一场冒险。他举的例子是 Fox 公司，全公司换成 Serval，负责迁移的那个人被提名为全公司的 MVP。

小苇

你听完怎么看？

大雨

我最认同的是"权限越收越紧"这个判断，它跟很多人的直觉相反。大家通常觉得智能体越强，人能做的事越多；他说的是在大企业里，能力放大的同时，默认权限会缩小，中间那一层审批才是要建的东西。

也要保留两点。第一，这个判断正好是他的生意，权限越紧他越值钱，听的时候要记得这一点。第二，两百人、Fox 这些都是他自己的说法，节目里没给收入等硬数字。

◈ 本周其他集数

小苇

这周还有哪些值得听？

大雨

第一集是《Latent Space》，十月三十一号，Arca 的 AI 负责人 Aman Singh。Arca 是一家 AI 原生的财富管理公司，刚融了四千八百五十万美元。这集正好和主推对着听：智能体做大部分后台工作，但交易和资金转移只能由人类顾问来做，他说"我们所有的安全限制都是确定性的"。他们的任务可以拖十天，所以每个客户都有一套持久记忆。他们自己做 harness，按内部评测自动选模型，也方便换供应商。标题来自他的一句话："智能体提示人，比人提示智能体更多。"

📎 来源：Agents Prompt People: Using Agents for Long-Horizon Financial Work — Aman Singh, Arca · Latent Space
小苇

第二集？

大雨

还是《Latent Space》，十月二十八号，Supabase 的两位创始人 Paul Copplestone 和 Ant Wilson，题目叫"为什么智能体喜欢 Supabase"。主持人 swyx 自己做的追踪显示，前沿模型推荐应用后端时几乎都选 Supabase。几个具体的点：不用 Docker 就能在本地跑，数据库结构用声明式文件放进 Git，让智能体可以直接读和改；计算放在数据库旁边。他们说现在每个月新建大约五百万个数据库，而且 AI 带来的用户转化率更高，因为智能体能把人从注册一路带到能跑起来。

📎 来源：Why Agents Love Supabase · Latent Space
小苇

还有吗？

大雨

第三集也是《Latent Space》，十月二十七号，Anthropic 的 Katelyn Lesse 和 Angela Jiang，讲 Claude 平台背后的工程：Opus 5.5 的发布、托管智能体，还有一个叫"把大脑和手分开"的设计，就是模型的推理和智能体执行动作分离，凭证和沙盒单独保护。一小时四十七分钟，适合做智能体基础设施的人。

最后提一下 Lenny's Podcast 十月二十五号那集，嘉宾是《The Power of Pull》的作者 Rob Snyder，一小时二十六分钟，讲怎么找到产品市场契合。我们没有拿到这集的详细内容，就只提一下。

◈ 关注建造者 · 本周建造者在说什么

小苇

这周建造者们在说什么？

大雨

点赞最高的是 Claude 官方账号，两万七千多个赞。他们把 Max 套餐改了名：Max 5x 还叫 Max，每月一百美元；Max 20x 改叫 Ultra，每月两百美元，价格不变。同时，通过验证的 Ultra 账号取消五小时限额，大部分现有订阅用户今天开始生效，新账号要先验证，这是为了防欺诈和滥用。每周限额不变。Boris Cherny 和 Alex Albert 也转发了。

小苇

有人不买账吗？

大雨

有。Peter Steinberger 那条四千多个赞，他说："这又是一个理由，用你自己的 harness，不要用那种公司可以随时改变你能做什么的。"这跟 Arca 那集自己做 harness 的理由是一样的：可以换模型供应商。

小苇

跟主推那集有关的呢？

大雨

Replit 的 CEO Amjad Masad 发了一份白皮书，讲怎么正确地给智能体做沙盒，在提高效率的同时降低风险。这条赞不多，但跟 Serval 讲的"一点一点放权"是同一个问题。

还有一条是前 Claude Code 团队的 Thariq，一千九百多个赞："解决经济悲观主义的办法，是更加 AGI-pilled。"他相信一个对齐良好、能解释自己工作、能带着人一起走的超级智能，让每个人都发挥到最大。后面一条他补充说，大家都不擅长预测智能会怎么进入经济，"会很贵、会让所有人失业"这个最简单的答案，其实并不够 AGI-pilled。

◈ 结尾 · 这周你打算听哪一集

大雨

这周几集放在一起，讲的是同一件事：智能体能做的越来越多，但在企业和金融这种地方，谁来批准、谁来记录、谁来担责，才是落地的关键。Serval 做权限审批这一层；Arca 让钱只经过人手；Anthropic 把大脑和手分开；Supabase 让智能体能看懂后端的状态。

小苇

对普通团队有什么可以马上做的？

大雨

看一眼你给智能体开的权限。它现在能碰到的东西里，有多少是这个任务真正用得上的？先收到最小，需要时再一项一项批。

小苇

那这周你打算听哪一集？

大雨

我会先听主推那一集，后半段讲后台智能体和 SaaS 末日那部分最值得听。然后听 Arca 那集，二十六分钟，正好跟主推对照。

小苇

我们下周见。

大雨
