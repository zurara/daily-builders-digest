🎙 播客对话 · 大雨 × 小苇
大雨 · 开场
这周的主推，来自 Every 家的《AI & I》，主持人是 Dan Shipper，嘉宾是 Granola 的联合创始人兼 CEO，Chris Pedregal。Granola 是这一波里最早让人「卧槽这个真的能用」的 AI 应用之一——一个开会时帮你记笔记、会后帮你整理的工具。但这一集真正好看的地方，不是产品本身，而是 Chris 极其坦诚地在聊一个所有 AI 应用创业者都在半夜想的问题：当 OpenAI、Notion、Zoom 都来抄你，当大模型自己就会做 Agent，你这家小公司凭什么还站得住？
小苇
我喜欢这种嘉宾——不端着。他一上来就打了个比方说自己现在是「在冲浪板上尽量别摔下去」，对吧？
大雨
对，这个比方特别真实。他说创业通常是你趴在冲浪板上拼命划水、等一道浪；而现在，他是站在了那道最大的浪上，动作从「怎么等到浪」变成了「怎么别被浪拍下去」。他说得很直白：创业是打刀战，我以前以为只有做不起来的时候难，结果发现做起来了一样难，只是难的东西不一样了。
小苇
那我们顺着他最焦虑的那件事先说——被抄。Notion、OpenAI、Zoom 都上线了几乎一样的会议记录功能。这对一家公司来说通常是噩梦，他怎么看？
大雨
他的答案出乎意料地平静。他说，这件事对公司的影响，比我原本担心的小太多了。因为最坏的那个场景——某某巨头上线同款的那一天——已经真实发生过了，反而让他不用再天天在脑子里预演那个噩梦。而结果是，他们的增长曲线没有任何变化。他补了一句很关键的话：我们到现在依然只是沧海一粟。所以他真正的判断是——现在还是极早期，别把注意力放在谁抄了你，放在还没被服务好的绝大多数人身上。
小苇
这集里有一个我第一次听到的说法，叫「Codex-native app」，Codex 原生应用。这是什么意思？
大雨
这是整集最有前瞻性的一段。Chris 说他最近自己 vibe code 了一个实验性的邮件客户端：他的每一封邮件，都变成 Codex 里的一张卡片，卡片上写着「这封邮件说了什么、我建议你这样回、要发吗」，然后他就跟它对话。他把这类应用叫做 Codex 原生应用——应用只负责两件事：保存状态、渲染界面；而那个聪明的 Agent，是你自己带进来的。
小苇
听出颠覆了。传统上，Granola 得自己造一个又好又聪明的 Agent，而且还要跟 Claude、Codex 这些同样在造 Agent 的巨头正面竞争。
大雨
完全正确。Chris 自己就说得很清楚：你想想 Granola 为了做一个好用的 Agent 得花多少功夫，太难了，而且你还在跟全世界最强的那几个 Agent 硬碰硬。所以他抛出了一个很反直觉的愿望——我其实很想把我自己的 Agent 带进 Granola。产品未来可能不再是「我给你一个封装好的 Agent」，而是「我给你一个漂亮的容器，你带你信任的那个 Agent 进来用」。这个范式如果成立，是要重新想护城河到底在哪的。
小苇
那如果 Agent 是用户自带的，产品的价值到底落在哪？Granola 打算守住什么？
大雨
他给了一个很成熟的答案，我觉得是这集最值钱的一句。他说：不要问要不要做通用的东西，要问有没有哪一件很窄的事，是我们能做到全世界最好的。他举了个真实用户的例子——有人开完会习惯立刻在 Granola 里写跟进邮件，因为那个场景下、那一类邮件，Granola 能做到别人做不到的好。他说，我不需要接管你整个收件箱，但会后那一封邮件，我可以是全世界最好的。
小苇
我注意到 Dan 和 Chris 之间还有一段特别好的对话，是关于团队怎么搭的。Dan 提了一个海盗和建筑师的模型？
大雨
对，这段是送给所有在 AI 时代重新想团队结构的人的。Dan 说，尤其是早期产品，只有两个角色最要紧：一个叫海盗 pirate，一个叫建筑师 architect。海盗的任务是用最快的速度造出来、去找到那个有价值的东西，可以纯 vibe code，不用管架构漂不漂亮；建筑师则跟海盗结对，负责把它变成一个可持续、能理解、能扩展的系统。
小苇
有意思的是他说这两个角色的配比不一样。
大雨
对，这点很实用。他说你每个产品需要一个海盗，但一个建筑师可以同时管好几个产品——因为现在工具太强了，一个好的架构师可以让 Claude 或 Codex 花一小时把一个陌生代码库给他讲明白，识别出那几根结构支柱，然后甩给 Codex 去做个二十四小时的重写，自己转头去干别的。AI 不是把人替掉了，是把一个人的作用半径放大了。
小苇
最后我想聊那个特别反直觉的成本哲学。Granola 会为了用户，生成上百万份会议简报，哪怕只有一成会被打开？
大雨
是的。Chris 说，我们宁愿先生成几百万份简报，哪怕只有一成被打开——因为我们要先搞清楚，对用户来说什么才是那个对的体验。至于成本，他的信念是两条：长期看单位成本一定会降；等我们知道了最好的体验长什么样，再回头去优化成本。还有个数字很有意思：每周大约有一半的 Granola 用户，其实已经在以 Agent 的方式用它了——只是他们自己不会用「Agentic」这个词来形容。
小苇
用户在用 Agent，但不知道那叫 Agent——这句话可以贴在每个产品经理的墙上。
大雨 · 收尾
这一集为什么值得从头听：它不是一集产品宣传，而是一个站在浪尖上的建造者，非常诚实地把第一波 AI 应用之后会发生什么摊开讲——被巨头抄不可怕，模型自己会做 Agent 也不可怕，可怕的是你没想清楚：在这个人人都能造 Agent 的世界里，那件只有你能做到最好的窄事，到底是什么。
◆ 三个记忆点
MAIN TAKEAWAYS
01被巨头抄不是终点。OpenAI / Notion / Zoom 都上线了同款会议记录，Granola 的增长曲线却没变——因为「最坏场景」发生后反而不用再预演噩梦。现在还是极早期，注意力应放在没被服务好的绝大多数人身上，而不是谁抄了你。
02Codex 原生应用：应用只负责保存状态 + 渲染界面，聪明的 Agent 由用户自己带进来。当大模型自己就会做 Agent，产品别再跟巨头硬拼 Agent 能力——去做那件你能做到全世界最好的窄事（比如「会后那一封邮件」）。
03团队与成本：海盗负责快速 vibe code 找价值，建筑师负责把它变成可扩展的系统——一个建筑师可管多个产品，AI 放大了人的作用半径。成本哲学是先找对的体验、再优化成本；每周约一半用户已在「以 Agent 方式」使用，只是没意识到。
