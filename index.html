◈ 本周主推 · Latent Space × Zeno Rocha (Resend)

📎 来源: Designing for Agents — Zeno Rocha, Resend · Latent Space

大雨

周日好，欢迎回到每日快报的播客时间。这周主推是《Latent Space》十一月十号上线的一集，八十六分钟，题目叫 Designing for Agents，为智能体设计。嘉宾是 Resend 的联合创始人兼 CEO Zeno Rocha。Resend 是一家做邮件发送 API 的公司，2023 年 YC 冬季批次。

小苇

一家发邮件的公司，为什么值得做主推？

大雨

因为这集是从一个很具体的疑问开始的。主持人 swyx 自己的域名都在 Cloudflare 上，Cloudflare 也有邮件服务，用起来很顺手。可是他让编程智能体帮忙接邮件功能，智能体一次次推荐 Resend，而不是他已经在用的 Cloudflare，也不是更老牌的 SendGrid。他们就把 Resend 的 CEO 请来问：你到底做了什么？

小苇

有数据吗，还是只是感觉？

大雨

节目页面引用了一项研究。研究者从 Claude Code 的回答里提取出 102 次邮件服务推荐，Resend 排第一的有 64 次。SendGrid 排第一只有 7 次，但作为"备选"出现了 55 次。

小苇

备选出现 55 次，听起来也不少。

📎 来源: Claude Code Picks · Amplifying research

大雨

主持人在这里问了一个关键问题：开发者让智能体实现邮件功能，接受了补丁，之后有多少人会回头去试第二个选项？大概很少。所以排第一和排第二，差别非常大。

公平起见也要说，Latent Space 自己后来做了一次更全面的测试，结果竞争激烈得多，多数模型排第一的是 Postmark，不是 Resend。

小苇

那 Resend 具体做了什么？

大雨

先讲背景。Resend 2023 年才上线，比 SendGrid、Postmark、Mailgun 晚了差不多十年，搜索排名上完全没有优势。Zeno 的第一个办法是给每一种长尾组合都写一篇短文档。不只写"用 Python 发邮件"，还写"用 Django 发邮件"，诸如此类。

后来大家开始问模型而不是问 Google，他就改了页面的格式。现在 Resend 几乎每个页面结尾都有一段常见问题，文档和官网都发布了 llms.txt，每个营销页面都有一个 Markdown 版本，在网址后面加 .md 就能拿到。

小苇

这个 .md 的做法，节目里有个例子吧？

大雨

对，定价页。Resend 的定价页有一个滑块，人拖到自己的发送量，就能看到价格。Zeno 有一次让模型比较"每月发 120 万封邮件，Resend 和竞品各要多少钱"。模型把 Resend 的价格算错了很多，还说 Resend 的定价不透明。

小苇

因为模型不会拖滑块。

大雨

对。那是一个 JavaScript 计算器，智能体抓页面时不会执行它。他说的原话大意是：JavaScript 组件不会被执行，所以我把同样的数据用文字写出来。他做了一个 Markdown 版本，把价格表直接写清楚。几天后再问，模型答对了。

小苇

他怎么知道有没有智能体来读这些页面？

大雨

他在 Datadog 里看这些 Markdown 页面的访问量，因为普通的网站分析工具根本看不到这类请求。另外 Resend 还付费用了四个 AEO 追踪工具。AEO 是 answer engine optimization，答案引擎优化。但他说这些工具只告诉你被提到了几次，不告诉你该做什么。

小苇

那该怎么做？

大雨

最简单的一步是自己去问。他发现定价错误，就是某个周日自己跑了一遍竞品对比。主持人也给了一个可以马上做的检查：打开你自己的定价页，看模型能不能用它回答一个客户的真实问题。

小苇

节目里有一段讲 MCP 工具数量，我挺好奇。

大雨

这段很有意思。Resend 的 MCP 服务器刚推出时大概二十个工具或更少，现在超过八十个。他想做到的是：在聊天客户端里，能完成仪表盘上能做的所有事。不只是发邮件，还有邀请同事、看用量、管账单，甚至删除账号。

小苇

八十个工具，模型不会挑花眼吗？

大雨

这正是主持人拿来对比的。Cloudflare 的 Code Mode 服务器只暴露两个工具，search 和 execute，让模型自己写代码去调 API。两种思路正好相反。Zeno 的看法是，他已经看不到模型因为工具太多而犯糊涂了，所以每次发布都多开放一部分产品。

小苇

那谁对？

大雨

节目没有给结论，但给了一个更实用的观察。Zeno 会把自己会话里折叠起来的工具调用展开，看智能体实际干了什么。有一次，一个工具返回的结果太大，塞不进上下文。减少工具数量并不能让这个返回值变小。

所以主持人建议：挑一个你每天都会调的工具，展开它的返回结果，看看模型到底需要其中多少。这比争论"二个还是八十个"更有用。

小苇

MCP 的使用量有多大？

大雨

他说调用量至少每个月翻一倍，八月份大约 120 万次。还有个小故事：Resend 第一个 MCP 服务器其实是投资方 a16z 的一个人写的开源项目，后来 Zeno 请她把项目转给了 Resend。做远程托管版本之前，他们得先加 OAuth、重做权限模型。

小苇

他自己作为买家，会因为 MCP 选产品吗？

大雨

会，而且很坚决。他把网站分析从 Plausible 换成了 PostHog，原因是 PostHog 自己维护官方 MCP 服务器，而 Plausible 的是第三方做的。他选消费类应用也一样，原话是：如果它不在那里，我就不用。

小苇

这对做 B2B 软件的人是个信号。

大雨

对。他想让产品变成"没有固定形态"的：先有 API，然后是为每种语言手写的 SDK，他拒绝了自动生成的 SDK，再然后是命令行工具和 MCP。现在有客户告诉他，从来没打开过他花了很多心思设计的仪表盘。

小苇

智能体选了 SDK，事情就结束了吗？

大雨

没有。邮件最难的部分在"发送"之后，就是能不能进收件箱。节目讲了一个例子：点击追踪。服务商会把邮件里的链接改写成经过一个共享的追踪域名，用来统计点击。如果某个客户用这个域名发钓鱼邮件，域名被拉黑，其他客户完全正常的邮件也会受影响。所以 Resend 推出了自定义追踪域名。

小苇

免费套餐不会招来很多发垃圾邮件的人吗？

大雨

会。老牌服务商的做法是新账号填表，等两天人工审核。Resend 反过来：先让所有人进来，然后盯退信率、投诉率和域名信号，比如一个两天前才注册的域名，或者一个打不开的网站。他说曾经有一伙人带着大约两万个域名来注册。他还说，被封的账号大多数其实是误用，不是恶意滥用。

一位 Mailgun 创始人曾经提醒他，Mailgun 九成的研发都花在对付滥用者上。所以 Resend 很早就把这部分做成自动化。

小苇

支持团队怎么撑住这么多用户？

大雨

Resend 现在有 430 万用户、12 万付费客户，去年十二月还只有 100 万用户。早期有一条规则对知识库帮助最大：回复工单只能贴链接。如果文档还不存在，客服就先去写文档，哪怕要写一个半小时。

现在大部分工单还是 DNS 配置问题，而且越来越多来自用 Lovable、Bolt、v0 做应用的人，他们以前从没见过 CNAME 记录。Resend 接入了一个用的人不多的协议，叫 Domain Connect，作用有点像域名版的 OAuth，Cloudflare 已经支持，他又说服了 Vercel 也支持。

小苇

他有没有说哪件事做错了？

大雨

有一个。Resend 当初做的是迁移页面，带一个代码转换器，帮你从别家迁过来，而没有做正面对比页。他现在觉得这是个错误，因为竞争对手的对比页更容易被模型推荐。

小苇

你听完怎么看？

大雨

我觉得这集最有用的一句话不是 Zeno 说的，是背后的那个变化：买家的第一个问题现在先问模型，而模型只给一个答案，不像 Google 给十条链接。

要成为那个答案，Resend 做的事都很朴素：每个页面都有模型能读的文字，官方 MCP 覆盖整个产品，免费套餐不设门槛。没有哪一步是花招。

小苇

我会补一句：React Email 那段也很值得想。

大雨

对。Resend 最早的分发不是靠发送 API，而是 React Email 这个模板工具。你可以用它做模板，再通过 SendGrid 发出去，他们甚至写了文档教你这么做。等开发者需要换服务商时，Resend 的代码已经在他的仓库里了。这在智能体时代可能更重要：模型在你的代码库里看到什么，就更可能推荐什么。

◈ 本周其他集数

小苇

这周还有哪些值得听？

📎 来源: What Frontier Labs Buy: A Data Deep Dive with Handshake AI — Garrett Lord & Team · Latent Space

大雨

第一集还是《Latent Space》，十一月九号，Handshake AI 的 Garrett Lord 和团队，一百六十四分钟。Handshake 的 AI 训练数据业务大约一年从零做到 10 亿美元年化总收入。这集现场演示了他们给前沿实验室做的强化学习环境：一个模拟投行，智能体要从邮件里找到任务、算出一个财务模型；一组脑肿瘤切片，要找出坏死最严重的两张。人选了两张，模型选了那两张又多加了一张。

小苇

投行那个例子模型错在哪？

大雨

客户邮件里有一行关于已有商誉的说明，智能体把这个数字带进 Python 直接减掉了。嘉宾说，你直接问模型税务处理，它能讲清楚；它错在没认出"这一行代码就是该用这条规则的地方"。我觉得这对做垂直领域智能体的人很有参考价值。

小苇

第二集呢？

📎 来源: Why PMs are suddenly valuable again | Tulsee Doshi · Lenny's Podcast

大雨

Lenny's Podcast，十一月八号，Google 前沿模型产品负责人 Tulsee Doshi，五十九分钟。她负责 Gemini，以及 Nano Banana、Veo、Lyria 这些多模态模型。重点有两个：一是她的 60-20-20 框架，用来平衡"现在能用的"和"快能用的"；二是怎么写你的第一个评测。她说做模型开发有点像斯内普的魔药课，加了配料不一定得到你想要的结果。

小苇

还有吗？

📎 来源: How Stanford Teaches AI-Native Engineering — Mihail Eric, Monaco · Latent Space

大雨

简单提一集。《Latent Space》十一月八号，Stanford CS146S 课程的老师 Mihail Eric，一百二十一分钟。问题很直接：编程智能体一个提示就能做完去年的作业，那该布置什么？他的答案是请开源项目维护者进课堂，学生要读懂一个陌生仓库、提出改动、再向可能合并它的人解释这个补丁。节目里还有一句他团队的原则：买是为了学，建是为了留。

小苇

这周建造者们在说什么？

📎 来源: Garry Tan on X

大雨

跟主推最接近的一条来自 YC 的 Garry Tan。他用自己开源的评测仓库，在 Claude Code 里跑了 52 个编程任务：Fable 5.2 解出的数量跟 Opus 5.5 差不多，82.7% 对 84.6%，但每解出一个任务的成本是 2.8 倍。所以他建议把 Opus 5.5 留作编程默认模型。他也说了，这些任务 Opus 已经大多能解，要分出高下得用更难的题。

小苇

这跟 Zeno 那个"自己去问模型"是一回事。

📎 来源: Nikunj Kothari on X

大雨

对，都是别只看别人的榜单，用你自己的任务去测。FPV Ventures 的 Nikunj Kothari 也说了类似的话：他以为 Llama 4 之后大家不再拿刷榜当卖点了，结果又回来了；要知道哪个模型好用，只能拿它跑你自己的工作流。

小苇

点赞高的呢？

📎 来源: Guillermo Rauch on X

📎 来源: Dan Shipper on X

大雨

Vercel 的 CEO Guillermo Rauch 发布了 Workflow SDK 5 和 Vercel Workflows。他说智能体执行时"到第一步的时间"和"步与步之间的时间"都大幅缩短，加强了加密和安全，可靠性也在大规模下验证过。

还有 Every 的 Dan Shipper，写了一篇文章讲：就算 Fable 5.2 什么都能用 vibe coding 写出来，为什么团队还在为软件付钱。这跟 Zeno 说的正好呼应：客户付钱买的不只是代码，还有送达率、反滥用、支持这些代码之外的东西。

◈ 结尾 · 这周你打算听哪一集

大雨

这周几集放在一起，有一条共同的线：读你产品的，越来越多是模型。Resend 给每个页面写 Markdown 版本；Handshake 给模型造模拟投行；Stanford 的课在智能体能做完作业以后，改成让学生读懂陌生仓库、把补丁讲给维护者听。

小苇

对普通团队有什么可以马上做的？

大雨

今天就做一件事：打开你们产品的定价页或者文档首页，复制网址，让一个智能体去回答"我每月要用多少，要付多少钱"。如果它答错了，看看是不是关键信息藏在 JavaScript 组件里。

小苇

那这周你打算听哪一集？

大雨

我会先听 Resend 那集里讲 MCP 设计和定价页的两段，大概第三十八分钟和第五十八分钟开始。然后听 Handshake 那集讲投行环境和评分的部分，从一小时十二分开始。

小苇
