🎙 对话全文 · 大雨 × 小苇
一次发二十个
大雨 · DAYU
欢迎来到 Daily Builders Digest，今天是二〇二六年九月三十号，星期三，产品日。我是大雨。
小苇 · XIAOWEI
我是小苇。昨天是 OpenAI 的开发者大会 DevDay，我看到的数字是二十多个发布。
大雨 · DAYU
官方说法是「超过二十个主要发布」。Every 的 Dan Shipper 从二〇二三年起每届都去，他说这是 OpenAI 发得最多的一次。
小苇 · XIAOWEI
发得多是好事还是坏事？
大雨 · DAYU
今天就聊这个。四条新闻：OpenAI 的常驻 agent Dots；ChatGPT 自己做文档和幻灯片；ChatGPT 向开发者开放成一个平台；最后是 Apple，新 CEO 要让 Apple 发产品更快、更频繁。四条放一起，问的是同一件事：发得快，用户跟不跟得上。
01Dots：关掉网页也在干活的 agent
大雨 · DAYU
先说事实。Dots 是 OpenAI 这次最大的新产品，一种常驻的 agent。它跑在 GPT-6 Astra 上，每个 Dot 有自己的云端电脑，你关掉网页它还在干活。它通过插件能连四千多个应用，可以在 ChatGPT 里用，也可以在 Slack 和 Teams 里用，还能打电话跟它说话。
小苇 · XIAOWEI
谁能用？
大雨 · DAYU
Pro 和 Business Premium 用户，第一个 Dot 包含在套餐里，不另收钱。跟 Dot 的对话也不算进 ChatGPT 的用量额度。企业、教育、医疗版是测试版，默认关闭，要管理员手动打开。
📎 来源: DevDay 2026 Recap — OpenAI
小苇 · XIAOWEI
这个形态听起来不新。OpenClaw、Meta 的 Muse、Grok Bot，都是这个方向。
大雨 · DAYU
对，Dan Shipper 也这么说。他提前用了几天，给自己的 Dot 起名叫 Boo。他说好的时候很好：Boo 会帮他过滤 Slack 和邮件，他改签航班时，Boo 提醒他新航班和一条他还没读的 Slack 会议邀请冲突了。
小苇 · XIAOWEI
那不好的时候呢？
大雨 · DAYU
他说这个版本太多 bug，现在不推荐：权限经常出问题，消息会丢，Dot 经常连不上内置浏览器。还有一点我觉得更值得注意：他和他的 Dot 都会搞不清楚，这件事到底该在 Dot 自己的电脑上做，还是在主对话的浏览器里做，还是在 Dot 另开的一个对话里做。
📎 来源: Vibe Check: OpenAI DevDay 2026 — Every
小苇 · XIAOWEI
连 agent 自己都分不清在哪儿干活。
大雨 · DAYU
现场演示也卡了。演示的人用语音问她的 Dot，Dot 回「正在查」，然后又回「还在查」。Codex 负责人 Thibault Sottiaux 后来发推解释，说所有更新同时上线，拖累了现场演示，但以后还会坚持现场演示。
📎 来源: OpenAI DevDay 2026: every announcement — DEV Community
小苇 · XIAOWEI
我的问题是：这么多 bug，Dan 为什么还在用？
大雨 · DAYU
他自己说了：虽然烦，但他已经习惯先找 Dot，而不是新开一个 Codex 对话。这是做产品的人要看清楚的一点：一个形态对了，用户会忍 bug。但忍耐有期限。他给读者的建议是等一两周再试。
02ChatGPT 自己做文档、幻灯片和共享空间
大雨 · DAYU
第二条。OpenAI 发了一整套办公工具。ChatGPT Space 是团队共享的工作区，你、同事、ChatGPT 和你的 Dot 在同一个地方放文件。Pages 是一种新文档，官方说法是「为人和 agent 协作而做的文档」。协作幻灯片几周后上线，多人和 agent 可以同时编辑，能导出成 PowerPoint 或 Google Slides。
小苇 · XIAOWEI
这就是直接对着 Notion 和 Google Docs 去了。
大雨 · DAYU
Dan Shipper 就是在 Space 里写的这篇测评。他说了一个我之前没想到的好处：速度。Dot 通过浏览器去改 Google Docs，改动是一点一点爬进去的，因为 Google Docs 不是给 agent 设计的。在 ChatGPT 自己的文档里没有这个延迟。你还可以在文档评论里直接 @ 你的 Dot，不用回到对话框里说「去看一下那个文件」。
小苇 · XIAOWEI
还有个「保持更新」的开关？
大雨 · DAYU
对，打开以后 Dot 会自动让这份文档保持最新，适合路线图、公司制度这种一直在变的文档。
小苇 · XIAOWEI
那问题在哪儿？
大雨 · DAYU
迁移成本。Dan 自己也说，大多数 ChatGPT 用户，包括 Every 这家公司，协作都在 Google 和 Notion 里。而且有个细节很有意思：这次「用 ChatGPT 账号登录」的首批合作方里，就有 Notion。
小苇 · XIAOWEI
一边合作，一边做它的替代品。
大雨 · DAYU
这对做产品的人是个提醒：如果你的产品是一个「放东西的地方」，文档、看板、表格，平台方现在有理由自己做一个给 agent 用得更顺手的版本。你要回答的是：为什么 agent 在你这里干活，比在平台自己的文档里更好。
03ChatGPT 变成平台：插件扩展和「用 ChatGPT 付钱」
大雨 · DAYU
第三条，给开发者的。插件扩展，英文叫 plugin extensions。OpenAI 说，它把自己做 ChatGPT 功能用的那套平台开放了。你的插件可以在侧边栏有一个固定入口，可以做交互面板，让用户在对话旁边操作，还可以给你支持的文件格式做查看器。Sam Altman 的原话是：你可以直接在 ChatGPT 和 Codex 里做一个编辑器、一个仪表盘、一整个工作区。
小苇 · XIAOWEI
用户怎么找到这些插件？
大雨 · DAYU
有插件目录，ChatGPT 也会在对话里推荐相关插件。OpenAI 说的分发规模是 ChatGPT 每周十二亿用户。Dan Shipper 的评价是：这是 OpenAI 第三还是第四次做应用商店了，总有一次会成。
小苇 · XIAOWEI
另一个呢？「用 ChatGPT 付钱」是什么意思？
大雨 · DAYU
叫 Sign in with ChatGPT。用户用 ChatGPT 账号登录你的应用，在你应用里产生的 OpenAI 用量，算进用户自己的 ChatGPT 套餐额度。首批十六个合作方，包括 Devin、Notion、Vercel。
📎 来源: DevDay 2026 Recap — OpenAI
小苇 · XIAOWEI
也就是说，token 的钱从开发者身上，转到了用户的订阅上。
大雨 · DAYU
对。Dan Shipper 很早就预测过，AI 订阅会像手机流量套餐：你买一份，然后自己选在哪些应用里用。他说这对 Every 这种做工具的公司是好事，不用担心重度用户把 token 账单刷爆。
小苇 · XIAOWEI
代价是什么？
大雨 · DAYU
DEV Community 那篇分析说得直接：你的登录、你用户的额度、你的成本结构，都要经过 OpenAI 的账号系统。你省下了 token 成本，换来的是依赖。
📎 来源: OpenAI DevDay 2026: every announcement — DEV Community
小苇 · XIAOWEI
还有一个 Decisions API，我看很多人说这才是最重要的。
大雨 · DAYU
这个很小，但很实用。你给它一段上下文和一组固定答案，它从里面选一个。比如这封邮件要不要回、这个工单归哪一类、agent 下一步点哪个按钮。Every 的编辑测了一组电脑操作任务，七十八步里选对了七十六步，一般两百三十毫秒出结果。价格还没公布。
小苇 · XIAOWEI
为什么说它重要？
大雨 · DAYU
因为每个 agent 产品里都有大量这种小判断。现在大多是调一个大模型、给个格式、失败了再重试。一个答案范围固定的小模型，更快，也更好测试，因为所有可能的输出就是你自己写的那张列表。
04Apple 新 CEO：发产品要更快、更频繁
大雨 · DAYU
最后一条，换个公司。九月一号，John Ternus 正式接任 Apple CEO。九月二十九号，彭博的 Mark Gurman 报道，Ternus 正在改组公司，目标是加快产品开发、更频繁地发新品。
小苇 · XIAOWEI
具体怎么改？
大雨 · DAYU
报道里提到几件事。一是考虑减少对春季、秋季两次固定发布会的依赖，一年里随时发新设备。二是砍掉一部分中层管理岗位，减少工程师和高管之间的层级。三是他在内部说 Apple 要「更敢实验」，才能在 AI 时代保持竞争力。四是控制成本：二〇二七年的早期规划里，预算增幅缩小、人数持平、营销支出减少。
小苇 · XIAOWEI
已经有动作了吗？
大雨 · DAYU
有。过去两周，一些总监和工程项目经理被撤职，给几周时间在公司内部找新岗位，找不到就被裁。Siri、Vision Pro、AI 软件工程、Fitness+ 这几个团队也有缩减。内部经理对 Gurman 说，压力变大了，产品团队被要求在更短的时间里交付更多产品。
📎 来源: Apple Planning to Launch Products Faster and More Often — MacRumors
小苇 · XIAOWEI
读者评论怎么看？
大雨 · DAYU
MacRumors 评论区点赞最高的一条是：软件更需要这样。另一条说：缩短工程师和高管的距离是好事，但靠裁掉有能力的工程师来省钱是坏事，而且加快硬件节奏会不会拖累软件质量，还不知道。
小苇 · XIAOWEI
跟 OpenAI 放在一起看挺有意思。一家一次发二十个，一家想从一年两次变成随时发。
大雨 · DAYU
对。两家都在往「更快」走，但出发点不一样。OpenAI 的问题是发太多，用户看不懂。Apple 的问题是发太慢，用户觉得它落后了。中间有一个共同的约束：用户能消化的新东西是有限的。
今天的观察
小苇 · XIAOWEI
那回到开头的问题：发得多，是好事还是坏事？
大雨 · DAYU
Dan Shipper 那篇测评的最后一段，我觉得回答得最好。他说，这么快的更新节奏让他很兴奋，手动开一个个 Codex 对话已经显得有点过时了。但他也觉得累，也觉得乱。他的原话大意是：功能多、更新快，在连贯的时候是好事；可现在连他这种重度用户都有很多东西要搞清楚，而且不是每样都能用。下次打开 ChatGPT，如果要搞清楚的东西少一点，他会更高兴。
小苇 · XIAOWEI
所以速度不是问题，连贯才是问题。
大雨 · DAYU
我的看法是这样的。有了编程 agent，写代码变快了，功能的成本在降。但用户理解一个新功能的成本没有降。发布的速度可以翻倍，用户的注意力不会翻倍。所以现在做产品，要多问一句：这个功能发出去，用户要多花多少力气才能搞懂整个产品？
关注建造者
大雨 · DAYU
今天的建造者动态，挑几条跟产品有关的。
小苇 · XIAOWEI
点赞最多的是 Claude Code 的 Thariq，四千两百多个赞。他说：现在基本不可能有人直接「给你看他的 prompt」了，因为一切都靠参考资料、技能和例子。他经常先让 agent 去看他之前做的三个仓库，再上网找参考，再调别的 AI 接口。
大雨 · DAYU
这跟做产品有关系：好结果越来越依赖你喂给 agent 的上下文，而不是那一句提示词。
小苇 · XIAOWEI
第二条是 Codex 负责人 Thibault Sottiaux，DevDay 前一天发的。他说二百美元的 Pro 套餐重新开放新用户订阅，但用量的计算方式变了，换算下来，相当于旧套餐 API 等价额度的一半。
大雨 · DAYU
这条值得看，是因为他在坏消息出来之前先讲清楚了。他解释了原因：不会再加回五小时限制；随着模型变便宜，同样的钱能做的事会越来越多；他们也不想为了让订阅显得划算，故意抬高 API 标价。先说坏消息、再讲为什么，这是一种做定价沟通的方式。
小苇 · XIAOWEI
第三条是投资人 Nikunj Kothari。他问：那些说「分发就是护城河，所以要多融钱」的投资人现在去哪了？现在是大公司在秀分发能力。他的建议是：回到第一性原理，找你的不公平优势，做留存高、最好有网络效应的产品，把钱当武器而不是命运，最后想办法自己养活自己。
大雨 · DAYU
这条放在今天特别合适。ChatGPT 每周十二亿用户，自己做文档、做 agent、开插件商店，这就是大公司在用分发。
小苇 · XIAOWEI
最后是 Dan Shipper 自己的推：从二〇二三年起每届 DevDay 他都去了，这次是 OpenAI 发布最多的一次。
大雨 · DAYU
播客推荐一期 Lenny's Podcast，嘉宾是 Molly Graham，她在 Google、Facebook 都做过管理。这期讲科技行业现在的倦怠和孤独感，还有她那条有名的建议「把你的乐高送出去」，在 AI 时代为什么不再完全成立。她有一个观点：把事交给 AI 和交给一个人，本质上不一样，现在每个员工都在变成管理者，不管愿不愿意。
📎 来源: The grief, loneliness, and burnout sweeping through the tech industry right now | Molly Graham — Lenny's Podcast

小苇 · XIAOWEI
发得快不难，让人看得懂难。
大雨 · DAYU
