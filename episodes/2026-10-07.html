🎙 对话全文 · 大雨 × 小苇
只改我圈的地方
大雨 · DAYU
欢迎来到 Daily Builders Digest，今天是二〇二六年十月七号，星期三，产品日。我是大雨。
小苇 · XIAOWEI
我是小苇。上周我们聊的是 OpenAI 一次发二十个产品。这周呢？
大雨 · DAYU
这周的新闻小一些，但方向很一致。四条：Claude 进了 Google 文档、表格和幻灯片；Google 的图片模型 Nano Banana 2.1 可以只改你圈出来的那块；OpenAI 的 Decisions API 公开测试，只回答选择题；最后是 Codex 团队的二十八天承诺，每天发一个改进，做不到就给所有人重置用量。
小苇 · XIAOWEI
这四条有什么共同点？
大雨 · DAYU
都在回答一个问题：AI 改东西的时候，用户能不能决定改哪里、改多少、什么时候算数。
01Claude 进了 Google 文档、表格和幻灯片
大雨 · DAYU
先说事实。十月六号，Anthropic 发布 Claude for Google Workspace，公开测试，所有付费套餐都能用。它是 Google 文档、表格、幻灯片里的一个插件，Claude 开在文件旁边的侧栏里，能读你打开的文件，能看到你选中了哪段文字、哪些单元格、哪几页幻灯片，然后直接在文件里改。
小苇 · XIAOWEI
具体能改什么？
大雨 · DAYU
文档里，它可以改一句话、改一个标题的样式，不动周围的格式。大段改写会变成侧栏里的建议卡片，每张卡片标出要改的那一段，你点应用或者忽略。表格里，它能写公式、做数据透视表、做原生图表、加新的标签页。幻灯片里，它用你这份幻灯片自己的版式和主题做新页，做完还会自己检查有没有元素重叠、超出页面、或者字太难读。
📎 来源: Claude now works with Google Docs, Sheets, and Slides — Claude
小苇 · XIAOWEI
反过来也行？从 Claude 里改 Google 文件？
大雨 · DAYU
也行。同时发了 Google 文档、表格、幻灯片的连接器，也是测试版。在 Claude 里贴一个 Google 文件链接，或者让它新建一个，文件会开在对话旁边，你和 Claude 同时编辑。Claude 能访问什么，跟你自己在 Google 里的共享权限一致。
小苇 · XIAOWEI
我觉得最关键的是哪一点？
大雨 · DAYU
我看的是默认模式。默认叫「编辑前询问」，每一处改动先出一张确认卡片，写清楚要改什么，你同意了才落到文件里。另一个模式是「接受所有编辑」，它一路做完不停。默认值选了前者。
小苇 · XIAOWEI
这对做产品的人有什么启发？
大雨 · DAYU
两点。第一，用户的文件已经在 Google 里了，与其让用户把文件搬过来，不如自己搬过去。第二，AI 改的是别人的文件，默认让人先看一眼再落笔。改得快不难，改错了让人不敢再用，这个代价更大。
02Nano Banana 2.1：只改你圈出来的那块
大雨 · DAYU
第二条。同一天，Google 发了 Nano Banana 2.1，一个图片生成和编辑模型，基于 Gemini 3.6 Flash。Gemini App、AI Studio、Gemini API 和企业平台都能用。官方说这次改进了三件事：视觉设计、蒙版编辑、主体一致性。
小苇 · XIAOWEI
蒙版编辑是什么意思？
大雨 · DAYU
你在图上圈出一块区域，模型只改这一块，其他地方不动。以前很多图片模型是你说「把杯子换成红色」，它会重新生成整张图，背景、人脸都可能跟着变。Google Labs 的 Josh Woodward 发推说，蒙版编辑是他这次最喜欢的功能。
📎 来源: Nano Banana 2.1 Debuts at Half the Image Cost of Its Predecessor — Unite.AI
小苇 · XIAOWEI
价格呢？
大雨 · DAYU
便宜了一半。按 Gemini API 价格页，一张 1K 的图从大约六点七美分降到三点四美分，4K 的从十五美分降到七点六美分。一个提示里最多能放十四张参考图。
小苇 · XIAOWEI
模型卡有没有写缺点？
大雨 · DAYU
写了，而且跟今天的话题有关。已知限制里有一条：蒙版编辑时，指令有时只执行了一部分，画上去的标记有时会残留在结果里。还有小字和长段落渲染不好，偶尔会超时。
小苇 · XIAOWEI
所以「只改圈的地方」这个承诺，现在也不是百分之百兑现。
大雨 · DAYU
对。但方向是对的。用户要的不是每次都重来一张更好的图，是「这里改一下，别的别动」。这跟上一条 Claude 在文档里只改一句、不动周围格式，是同一个需求。
03Decisions API：只回答选择题
大雨 · DAYU
第三条。十月六号，OpenAI 的 Decisions API 进入公开测试。DevDay 上它只是小范围预览，现在所有开发者都能用。它跑在 GPT-6 Luna 上。
小苇 · XIAOWEI
它跟普通的 API 有什么不同？
大雨 · DAYU
普通的 API 你问什么它写一段话回来。Decisions API 只回答你事先定好的问题，答案范围也是你定的。有三种问题。判断题：这张商品照片有没有裂痕，它返回一个零到一的概率。选择题：这条客诉该分给账单、技术、物流还是其他，它返回选中的那项，加上每个选项的概率和一个置信度。打分题：这个问题严重程度是低、中、高，它返回一个分数。
📎 来源: OpenAI Releases Decisions API in Public Beta — Unite.AI
小苇 · XIAOWEI
快吗？贵吗？
大雨 · DAYU
OpenAI 说比 Responses API 快十倍左右。价格是每一百万输入 token 一毛钱，输出不收钱。上周我们提过 Every 的测试，七十八步电脑操作选对了七十六步，每次大约两百三十毫秒。
小苇 · XIAOWEI
那门槛是谁定的？比如概率到多少才算有裂痕？
大雨 · DAYU
开发者定。官方文档的建议是：用你自己生产环境里标注好的例子去校准阈值，想清楚误报和漏报哪个代价大。还建议在选项里加一个「其他」，模型拿不准的就送去人工审核。Vercel 的 Guillermo Rauch 转了这个功能，说「低于置信度阈值时，想得慢一点」，他认为这对大规模的 AI 判断影响会很大。
小苇 · XIAOWEI
这条为什么算产品新闻？
大雨 · DAYU
因为一个产品里大部分 AI 调用，其实不需要写一段话，只需要「选一个」。答案范围固定，就能测试，能统计，能给每个分支写好后续流程。把开放的问题收窄成选择题，是把控制权交回给做产品的人。
04Codex 的二十八天承诺
大雨 · DAYU
最后一条。十月四号，OpenAI Codex 的负责人 Thibault Sottiaux 在 X 上发了一个承诺：接下来二十八天，团队每天发一个对大多数 Codex 和 ChatGPT Work 用户有用的明确改进；哪天做不到，就给大家完整重置一次用量。
小苇 · XIAOWEI
第一天发了什么？
大雨 · DAYU
第一天，GPT-6 Astra 和 GPT-6.1 Sol 默认速度提高了大约百分之五十。他后来补充说，从每秒大约三十个 token 提到五十个。The New Stack 指出，按这两个数算其实接近三分之二，不过两个数都是估算，不是正式测试。
📎 来源: Developers are secretly hoping OpenAI fails to ship this month — The New Stack
小苇 · XIAOWEI
第二天呢？
大雨 · DAYU
第二天很有意思。他昨晚发推说，团队发了四个「还不错到很好」的改进，还有一些数学证明，但社区投票的结果很清楚，大家要重置。他说他算过，这个游戏规则好像本来就偏向重置，但规则就是规则。所以第二天给了重置，而且发出去的改进也不撤回。
小苇 · XIAOWEI
等一下，用户投票决定算不算改进？那用户当然投重置。
大雨 · DAYU
对，这就是问题。The New Stack 那篇文章的标题就是「开发者暗地里希望 OpenAI 这个月发不出东西」。有人开玩笑说这把用量变成了赌博：每天把额度用完，然后盼着 OpenAI 失手。还有个网站当天就做了一个二十八天的记分板。
小苇 · XIAOWEI
规则有没有写清楚？
大雨 · DAYU
没有。这个承诺只存在于他的推文里，不在 OpenAI 的条款里。哪些套餐能拿到重置、「完整重置」到底恢复哪些额度、日期从哪天算，都没说清楚。四月那次「所有付费套餐」重置，就有 Plus 用户在 GitHub 上提问题，说自己的周额度根本没动，后来客服解释说那次重置不覆盖所有额度类型。
小苇 · XIAOWEI
背景里还有一件事吧？
大雨 · DAYU
对。OpenAI 上周说，从十月三十号起，两百美元的 Pro 套餐里 Codex 和 ChatGPT Work 的额度，从 Plus 的二十倍降到十倍，同时加了一个五百美元、二十五倍的新套餐。这个时间点正好在二十八天快结束的时候。
小苇 · XIAOWEI
那你怎么看这个承诺？
大雨 · DAYU
我觉得想法是好的：把发布节奏公开，让用户来监督。但它跟前面三条正好相反。前面三条都在让用户更清楚地控制「改什么、怎么算」。这一条的「什么算改进」，规则没写清楚，最后交给了投票。用户会按自己的利益投票，这很正常。如果你要对用户做公开承诺，先把「什么算数」写下来。
关注建造者
小苇 · XIAOWEI
今天建造者那边有什么？
大雨 · DAYU
先说播客。Redpoint 的 Unsupervised Learning 第九十四期，请的是 Applied Compute 的 CEO。他做的是帮公司对开源模型做后训练。他说「拥有自己的智能」，重点不是担心大厂偷数据，而是灵活和控制：模型跑在哪、怎么部署、优化成本还是延迟，都要自己能决定。他还说，强化学习本质上是一台爬山的机器，最难的是定义要爬哪座山，所以评测集是公司最该花力气建、也最该保护的东西。
小苇 · XIAOWEI
又是控制。推文呢？
大雨 · DAYU
点赞最多的一条是 Claude Code 的 Boris Cherny。他说很奇怪大家会惊讶他这么写提示词：跟 Claude 说话就像跟同事说话，提示没有秘诀，大多数任务不需要写很多框架和规定，给它一个目标，它自己会想办法。
小苇 · XIAOWEI
这跟 Decisions API 好像是两个方向。
大雨 · DAYU
不矛盾。一个是你自己用 agent 干活，目标说清楚就行；一个是你在产品里调用模型，答案范围要固定。场景不同，控制的方式不同。
小苇 · XIAOWEI
还有吗？
大雨 · DAYU
Claude 官方号发了 Every 的案例：Every 尽量把工作都交给 agent，他们在 Claude Managed Agents 上搭了一个全公司在 Slack 里共用的 agent，新模型出来时方便大家共享技能，后来还把它上架了。同是 Claude Code 团队的 Thariq 说，以后 Claude 的「大脑」会越来越多地放在云上，再给它一双在你电脑上干活的「本地的手」。他也说了难点：如果电脑关机了 Claude 就读不到你的文件，活就卡住了，所以可能需要某种同步，但同步有很多边界情况。
小苇 · XIAOWEI
最后一条？
大雨 · DAYU
follow-builders 的作者 Zara Zhang 说：现在几乎不可能想出一个好的产品名，好名字都被用掉了。
小苇 · XIAOWEI
这个我同意。
结尾
小苇 · XIAOWEI
今天留一个问题给听的人？
大雨 · DAYU
看看你的产品里，AI 每次改东西的范围，用户能不能自己定。能不能只改选中的那一段、那一块、那一格？改之前能不能先看一眼？如果不能，下一个版本先做这个。
小苇 · XIAOWEI
改得多不难，只改该改的难。
大雨 · DAYU
明天是星期四，健康日。我们明天见。
小苇 · XIAOWEI
明天见。
