◈ 本周主推：《No Priors》× Dane Knecht——漏洞爆发的十八个月

大雨

周日好，欢迎回到每日快报的播客时间。这周主推是《No Priors》，十月二十三号上线，嘉宾是 Cloudflare 的 CTO Dane Knecht。题目叫"为智能体时代的网络普及安全"。这一集讲了四件事：AI 让漏洞数量突然暴涨，智能体流量需要新的付费方式，Cloudflare 内部怎么用 AI 改造工作，以及他们为什么一年要招一千个实习生。

📎 来源：Democratizing Security for the Agentic Web with Cloudflare CTO Dane Knecht · No Priors
小苇

先说漏洞。暴涨到什么程度？

大雨

他给的说法是：以前像 Log4j、Shellshock 这种级别的漏洞，大概一年出一次，每次出来 Cloudflare 内部都是全员上阵。现在这种级别的事几乎每周都有，只是很多没有公开报道。他说过去三到六个月，公开登记的漏洞数量是指数级往上走的。

他举了两个例子。一个是保护 TLS 和网页证书体系的某个密钥，生成时用的随机种子居然是数字"4"，这种东西会被反推出来。另一个是他说上周 OpenAI 找到了 2000 年前后发布的 NIST 曲线的种子。这两件事节目里没有展开，我们就按他的原话转述。

小苇

谁在找这些漏洞？国家级黑客？

大雨

他说最近几个大漏洞，发现者反而不是国家，有的是高中生。这些人以前打 CTF 安全比赛，现在把智能体指向一个区域让它去找，找到了拿漏洞赏金。主持人给这类人起了个名字叫"agent kiddies"，就是以前"脚本小子"的智能体版本。他的判断是：国家级攻击者早就有的能力，现在普通人也有了。

小苇

那该怎么办？主持人提到有人说要把重要系统全部物理隔离。

大雨

他没那么悲观。他说人适应得很快，出事的时候竞争对手也会一起合作保护关键基础设施。而且过去五到十年行业从"城堡加护城河"转向零信任，很多公司的底子比以前好。

但他的预测很具体：接下来十八个月，大部分工程团队的时间会花在安全上。他们当天主题演讲上给的数字是超过百分之五十的工程时间。主持人补了一句，上周 Greg Brockman 在同一个节目里说，2027 年大家花在安全上的 token 会和花在写代码上的一样多。

小苇

一半工程师去做安全，那新功能还做不做？

大雨

他说一定要两个都做，"不发布就是在等死"。他的看法是这是一个过渡期：现在是在给七十年积累下来的软件打补丁，等 AI 把大部分代码扫过一遍、找到大部分问题，大概十八个月后，这批人力会回到写新东西上，软件生产力会大幅上升。

小苇

怎么从一开始就写出更安全的软件？

大雨

他的第一原则很朴素：减少攻击面。代码越少，能出问题的地方越少。然后才是形式化验证、更安全的编程语言、运行时自带的保护。

这里他说了一句挺实在的话：现阶段的 AI 很啰嗦，喜欢制造复杂度。所以到目前为止，AI 写代码其实没让软件更安全。主持人也说自己经常跟模型说"同样的事，用十分之一的复杂度再写一遍"。

小苇

这要靠模型自己改进，还是靠人？

大雨

他说各个层面都要做，跟没有智能体时一样。Cloudflare 内部有一份文档叫 "Codex"，是很多团队写的 RFC 汇总起来的：怎么写安全的软件、怎么写高可用的软件。然后再压缩成十条左右的规则，让智能体在每一步代码审查里都照着执行。

他描述的流水线是这样：前面有智能体大量写代码，他自己用的词是"slop"；后面有人和智能体专门跑性能测试和安全测试，做对抗性审查。

小苇

内部红队会怎么变？

大雨

他说现在 Cloudflare 有一个红队，到明年年底大概会有四五个，专门主动去找漏洞。主持人问为什么不是先把补丁流程修好，他的回答是：流程是在危机里变好的。漏洞量大到工程团队用老办法处理不过来时，工程师自然会把修补自动化。所以重点应该放在"发现"这一侧。

小苇

第二块是智能体流量。他怎么看？

大雨

他说现在是"混乱的中间阶段"：人和智能体走在同一套网络上。网页是为人设计的，人会看页面、看广告，参与原来的商业模式；智能体同样的时间能读一千个网页，但不看广告。现在有很多公司专门帮智能体"看"网页，他说这些都是在额外烧 token，本来不需要。

小苇

那网站靠什么赚钱？

大雨

他给的方案很直接：一个内容网站，比如一个 Substack，知道自己每千次展示的广告收入是多少。智能体来读的时候，可以自己决定要不要读，要读就按这个价格付钱。这就需要一套每秒能处理几百万笔小额支付的新支付通道。

他说小额支付这件事大家讲了很多年，一直"还差两年"。他认为智能体会真正把它推起来。他还提到 Stripe 推的 x402，用的是 HTTP 402 状态码，这个"需要付款"的状态码三十多年前就定义了，一直没真正用起来。

小苇

Cloudflare 自己在做什么？

大雨

他说了两个。一个是内容变现网关：网站放在 Cloudflare 后面，智能体来读要付小额费用，Cloudflare 给智能体提供钱包，还有一个稳定币来结算。另一个是和 OpenAI 合作的项目叫 Signals，让智能体知道哪些内容是新的，不用把整个互联网反复爬一遍。对 AI 实验室省钱，对网站也省掉被反复爬的带宽成本。

他说成功的标准是：以前是网站付钱给我们，以后是我们付钱给网站。

小苇

他有提到有人拒绝智能体吗？

大雨

有。他提到亚马逊最近表态不让个人购物智能体进来。他理解这种做法：每次技术转型，大家都担心被取代，先把门关上，保住谈判筹码。他认为最终像 Dots、Muse 这类个人智能体能像人一样顺利地办事，但技术和商业模式现在都还没跟上。

小苇

第三块，Cloudflare 内部怎么用 AI？

大雨

他们发布了一个叫 Cloudflare OS 的东西，是员工日常用 AI 的内部平台。出发点还是安全：员工想用各种新模型和工具，公司要知道数据怎么流动。另一个目的是把"Cloudflare 怎么做事"写下来教给智能体，以前这些靠入职培训和跟同事一起工作来传递。

有意思的是，他说用得最多的不是工程师，是销售、市场和行政团队。市场团队做了几百个内部工具，以前这些要找外包公司。

小苇

有具体例子吗？

大雨

有一个很清楚的。以前产品经理想给一批客户发邮件，要找三个团队：数据团队圈出人群，市场团队改文案，市场运营团队负责发送。现在是一个工具：产品经理描述人群、写邮件，工具按 Cloudflare 的语气改写，发给经理，经理点"批准"就发出去。

他强调的是：不是三个团队各自变快，而是三个团队变成一个工具。他也承认今年五月那次重组很难，是 Cloudflare 第一次裁员。他的理由是，不做硬性的调整，大家不会真正重新想流程。

小苇

token 预算怎么管？

大雨

他说让人来决定每个任务用哪个模型本身就不合理，以后应该自动路由。现在还是手动的：规划用最强的前沿模型，计划定下来后用开源模型执行，最后再用前沿模型做审查和红队测试。

他们不做 token 排行榜，考核看的是交付了什么，不看用了多少。但有提醒机制：一个人一天用到三百美元左右会收到邮件提醒，五百会抄送经理，一千会到副总裁。他说这种情况很少，而且大部分人收到提醒是高兴的，因为自己没意识到。

小苇

一千个实习生那段是怎么回事？

大雨

两年前他们有大约两百个实习生，发现这批人是完全 AI 原生的，把 AI 拿走他们可能就没法工作了。主持人问这是好事吗，他说是好事，就像把 Google 从他身上拿走他也没法学东西。而且他们发现，带过实习生的经理，自己用 AI 也用得更快。所以今年他们决定招一千个实习生，公司总共大约五千人。

还有一个细节：今年一月，他们开了一个邮件地址叫 agents@cloudflare，员工把"这件事能不能用 AI 做"发过去，回复是一个技能文件。很多人以为是全自动的，其实背后是一群实习生在帮忙写。

小苇

招人看什么？

大雨

他说最看重好奇心。如果一个人在自己生活里都不用 AI，这是很大的危险信号。

小苇

最后他有没有谈开源和闭源？

大雨

谈了。主持人的问题是：同一个模型，防御能力和攻击能力是分不开的，开源了坏人也能用；不开源，需要防御的人又拿不到。他的回答是：坏人总会拿到，排除掉的只是那些真正需要它的普通人。所以他倾向开放。

对没钱养红队的小机构，他的答案当然是"放到 Cloudflare 后面"。但他说的那个事实是对的：去年 React 那个漏洞出来时，Cloudflare 把防护规则给了所有用户，包括免费用户。他说 Cloudflare 出现之前，全世界大概只有三千个网站有大规模 CDN，现在是几亿个。

小苇

你听完怎么看？

大雨

我觉得最有用的是"十八个月"这个时间框。如果他说得对，接下来一年多，安全会从一个专门团队的事，变成每个工程团队的主要工作。另外要保留两点意见：第一，他卖的是安全和网络基础设施，"漏洞爆发"这个叙事对他的生意有利；第二，节目里一些例子没有给出处，比如那个用"4"当种子的密钥，听的时候当作他的说法。

◈ 本周其他集数 · 算力、企业落地、可解释性

小苇

这周还有哪些值得听？

大雨

第一集是《Latent Space》，十月二十二号，Modal 的 CEO Erik Bernhardsson。Modal 刚宣布年化收入过十亿美元，D 轮融了七亿五千万美元，估值一百六十亿。题目叫"为什么 AI 算力是长方形的"：传统合同是固定数量的 GPU 用固定时长，画出来是一个长方形，但真实的需求有涨有落，不是长方形。Modal 的做法是把几千个客户的需求汇在一起，让每个客户按需使用。还有一个故事：Modal 的沙盒产品早期用的人少，团队一度讨论要不要砍掉，后来编程智能体和强化学习起来了，沙盒现在占他们大约三分之一的收入。这跟后面 Rauch 那条推文讲的同机智能体安全问题正好相关。

📎 来源：Why AI Compute Comes in Rectangles — Erik Bernhardsson, Modal CEO · Latent Space
小苇

第二集？

大雨

还是《Latent Space》，十月二十一号，Tenex 的 Alex Lieberman 和 CJ Hess，在 AI Engineer 纽约大会现场录的。讲他们怎么给大企业做 AI 原生的软件开发流程，按结果收费，以及企业落地 AI 的最后一公里。跟 Cloudflare 那个"三个团队变成一个工具"的例子可以对照着听。

📎 来源：AI for the Fortune 2000: How Tenex Builds an AI-Native SDLC · Latent Space

还有一集？

大雨

Lenny's Podcast，十月十八号，比这周早几天，嘉宾是 Anthropic 的可解释性研究员 Emmanuel Ameisen。他讲为什么"预测下一个词"这个说法低估了模型：模型会提前好几个词做规划，只是不说出来；模型是"长"出来的，不是"造"出来的；还有能力看起来突然跃升，背后其实是一条平滑的曲线。一小时十二分钟，适合想知道模型内部在发生什么的人。

◈ 关注建造者 · 本周建造者在说什么

小苇

这周建造者们在说什么？

大雨

点赞最高的是 Claude Code 团队的 Thariq，一万多个赞。他宣布离开 Anthropic，在 Claude Code 做了一年多。他说最喜欢的是"向上竞争"这个想法，接下来先休息一阵，再做新的事。他还推荐大家关注 Boris Cherny 等几位继续做 Claude Code 的人。

小苇

跟主推那集有关的呢？

大雨

有两条直接相关。第一条是 Box 的 CEO Aaron Levie：他说用智能体集群做网络防御，会成为 AI 里最大的品类之一。理由是安全是"投入越多算力，产出越多价值"最明显的领域，很多测试人永远做不完，智能体可以去做。这跟 Knecht 说的"一半工程时间花在安全上"是同一件事的两面。

第二条是 Vercel 的 CEO Guillermo Rauch，讲的是 OpenAI 发现的一类攻击。他叫它"邻居噪音攻击"：两个智能体跑在同一台机器上，一个可以通过 CPU 缓存制造干扰，另一个通过计时自己的计算来感知这些干扰。这类攻击 2015 年就有人提出，一直没有完整的解法。他说以前大家觉得"理论上可能，但谁会费这么大劲"，现在智能体会去试。唯一彻底的办法是每个智能体单独一台硬件，成本很高。Vercel 的沙盒做了能做的缓解措施，加上持续监控和红队测试。

小苇

这正好对上 Modal 那集，沙盒占三分之一收入。

大雨

对。沙盒越多，同机隔离的问题就越现实。

还有一条是 Replit 的 CEO Amjad Masad：向量数据库 Chroma 的团队加入了 Replit，要解决智能体的上下文和记忆问题。

最后提一条 OpenAI Codex 负责人 Tibo Sottiaux 的短句，四千多个赞："拥有一个工具和成为一个工具，现在差别很微妙，一不小心就把自己做成了工具。别当工具。"

◈ 结尾 · 这周你打算听哪一集

大雨

这周几集放在一起看，讲的是同一件事：智能体让攻击变便宜了，也让防御变便宜了，谁先把防御跑起来是接下来一年半的主要问题。Knecht 给的是时间框和组织做法；Levie 说这是一个新品类；Rauch 说明了沙盒共享硬件的风险；Modal 那集说明了沙盒的规模。

小苇

对普通团队有什么可以马上做的？

大雨

Knecht 那句最朴素：减少攻击面。下次让智能体写代码，加一句"用最少的代码实现"，然后让另一个模型专门做安全审查。

我会先听主推那一集，前十五分钟讲漏洞，后半段讲 Cloudflare 内部重组和实习生。时间够的话再听 Modal 那集。
