🎙 今日播报 · 大雨 × 小苇
开场
大雨
欢迎来到 Daily Builders Digest，今天是二〇二六年十一月二十五号，星期三，产品日。我是大雨。
小苇
我是小苇。上周我们聊的是小范围上线。这周呢？
大雨
这周四条。第一条，Anthropic 发布 Claude Ship，三个 agent 负责代码写完以后的事：审查、修复、批准。第二条，Claude 里做的小工具，现在可以装成 Mac 和 Windows 上的独立 app。第三条，谷歌把 Gemini 里一个开关拆成了两个：保留聊天记录，和允许拿去训练，以后分开选。第四条短一点，Claude 把连接器和技能合并成「插件」，放在一个入口里。
小苇
这四条有什么共同点？
大雨
都在处理「权限」这件事。以前一个开关管好几件事，现在拆开；或者反过来，入口合并了，但开关没合并。今天想看看每家是怎么拆的，拆完以后用户和管理员要多做什么判断。
01 · Claude Ship：代码谁来批准
大雨
十一月二十三号，Anthropic 发布 Claude Ship，测试版，给 Team 和 Enterprise 用户，针对 GitHub 上的仓库。它由三个 agent 组成。
📎 来源: Anthropic launches Claude Ship, letting AI agents review, fix, and approve code changes — TechCrunch
小苇
哪三个？
大雨
第一个是 Code Review，看代码改动，结合整个代码库找问题，把发现贴在 PR 上。这个已经正式上线了。第二个是 PR Steward，测试版，负责处理后续的活：CI 没过、合并冲突、Code Review 提的意见。它每次推送以后都会留言，说改了什么、怎么回滚。第三个是 Claude Approvals，也是测试版，按团队写的规则决定一个改动能不能批准。
小苇
规则写在哪里？
大雨
写成一个文件，放在仓库里，用自然语言写。Anthropic 的博客是这么解释动机的：大部分团队希望每个改动都有人批准，人写每一行代码的时候，这跟得上。但现在很多开发者用 agent 写代码。Claude Code 团队自己的代码大部分是 Claude 写的，他们希望 PR 之后的环节也一样快。
小苇
让 AI 批准 AI 写的代码，听起来有点吓人。
大雨
Anthropic 自己也建议慢慢来。先在一个仓库开，Approvals 先用「只观察」模式，就是它只告诉你它会批准什么，不真的算数。可以设每月花费上限，也可以指定哪些改动必须交给人决定。
小苇
那「只观察」以后呢？真的能不经过人就合并吗？
大雨
这要看 GitHub 那边的设置。Superpower Daily 读了一遍文档，对比了六种配置。结论有两条。第一条，如果仓库要求文件的代码负责人必须是人、必须批准，Claude 的批准替代不了这一步。第二条，如果团队把规则里需要人批准的数量设成零，又把这个检查设成必须通过，而且没有别的人工审查要求，那机器写的改动通过检查以后，就可以直接合并。
📎 来源: Claude's policy check does not replace required human code-owner approval — Superpower Daily
小苇
所以「要不要人」这件事，Anthropic 没有替你决定，是留在 GitHub 的分支规则里。
大雨
对。这是我觉得这个产品最值得注意的设计：批准权被拆成了好几层。Claude 的规则检查是一层，GitHub 的审查要求是一层，能不能合并又是一层。好处是每个团队可以自己调。坏处是，你得真的知道这几层是怎么叠在一起的，不然可能以为有人在看，其实没人。
小苇
还有一点，零数据保留、HIPAA 配置、客户自管密钥的组织，暂时用不了。
大雨
对，这些组织不在这次范围内。
02 · Claude 小工具装成桌面 app
大雨
第二条。十一月二十四号，Anthropic 推出一个测试功能，叫 Install as app。你在 Claude 里做的小工具，Anthropic 叫 artifact，现在可以装成 Mac 或 Windows 上的 app，有自己的图标，在单独的窗口里打开。
📎 来源: Anthropic lets Claude users turn custom tools into Mac and Windows apps — Superpower Daily
小苇
跟以前在浏览器里打开有什么区别？
大雨
省掉了几步：不用打包，不用代码签名，不用 API key，也不用另外登录。你在原来的 artifact 上改，装好的 app 也会跟着更新。但它不是独立的软件。打开它需要联网，需要 Claude 桌面端登录着，用量算在你的 Claude 套餐里。
小苇
那它能做什么？
大雨
这里就是权限的部分。默认情况下，装好的 app 能做的事，跟在浏览器里一样。要更多能力，得一项一项申请：通知、在别的 app 前台时也能用的快捷键、窗口置顶、Mac 菜单栏或 Windows 托盘图标。最大的一项叫「完全电脑访问」，可以运行程序、读写和删除文件，不用每次问你。
小苇
这个权限给谁？
大雨
只能给你自己做的 app，或者 Team 和 Enterprise 用户自己组织里做的 app。Anthropic 在帮助文档里说，安装之前它不审核这些 app，只有你信任每一个写这个 app 的人，才应该给这个权限。
小苇
授权一次就一直有效吗？
大雨
不是。授权只对一个版本有效。app 一更新，哪怕是你自己改的，Claude 都会再问一次。但有一个例外：app 从别的网站加载的代码，变了不会触发重新询问。另外，你可以撤销权限，但撤销不会把已经改掉的东西改回来。
小苇
「安装」和「授权」是两件事。
大雨
对，这是这个功能的核心设计。很多桌面软件是装上就有全部权限。这里装上只是第一步，权限要分开给，而且每个版本重新给。组织默认值也不一样：Team 默认可以安装，但完全电脑访问要管理员打开；Enterprise 整个功能默认关闭。
小苇
还有哪些不支持？
大雨
Linux、网页版、手机不支持。Claude 的 Docs、Slides、Sheets 不能装。HIPAA 配置的组织也用不了。
03 · Gemini：一个开关拆成两个
大雨
第三条，谷歌这边。十一月二十四号，Gemini app 更新了一项设置。以前有一个开关叫「Keep Activity」，现在换成了两个分开的控制，放在新的「Gemini History」设置里。
📎 来源: Google's Gemini app adds chat history and training controls — NewsBytes
小苇
拆成哪两个？
大雨
一个管要不要保留聊天记录，一个管要不要让谷歌用来训练 AI。以前这两件事绑在一起：你想保留记录，就得同意训练；你不想被拿去训练，就连记录也没了。
小苇
这个改动听起来很小。
大雨
改动小，但对用户影响很大。很多人关掉那个开关，并不是不想要记录，只是不想被训练。结果是丢了历史，下次找不到以前的对话。这在产品上是一种很常见的问题：两个用户意图不同的选项，被一个开关绑在一起。
小苇
为什么以前要绑在一起？
大雨
报道里没说原因，我只能猜。绑在一起，同意训练的人会更多，因为大部分人更想要聊天记录。拆开以后，训练数据可能会少一些。所以这个改动也说明，谷歌愿意为用户能分开选，付出一些数据上的代价。
小苇
这跟 OpenAI 的 Thibault Sottiaux 这两天说的「简化 app」是两个方向。
大雨
对，一边是把功能合起来，让界面更简单；一边是把设置拆开，让选择更准确。两者不矛盾：入口可以合，开关要按用户意图拆。
04 · 短消息：Claude 插件，入口合了，开关没合
大雨
最后一条短消息。十一月二十三号，Claude 官方账号说，连接工具、教 Claude 新技能，现在只有一个入口：连接器和技能合在一起，叫插件。Free、Pro、Max、Ultra 已上线，Team 和 Enterprise 稍后。官方说可以浏览一万多个插件。
📎 来源: Anthropic puts Claude's skills and connectors on one Plugins page — Superpower Daily
小苇
一万多个这个数字可靠吗？
大雨
这是 Anthropic 自己的说法。FourWeekMBA 去看了公开市场，当时列出来的是五百三十九个。可能是统计口径或者时间不同，先存疑。
📎 来源: Claude Folds Skills and Connectors Into 10,000+ Plugins — FourWeekMBA
小苇
跟今天的主题有什么关系？
大雨
入口合了，但管理没有完全合。一个例子：你删掉一个带连接器的插件，连接器并不会断开，要另外去断。另一个例子：十一月三十号起，Team 和 Enterprise 里关掉了「技能」的管理员，会发现桌面端的插件也被一起挡住，这个设置那天会改名叫「插件」。
小苇
所以管理员这周要做的一件事，是去看看技能开关现在是什么状态。
大雨
对。
关注建造者
小苇
最后是关注建造者。
大雨
今天挑四条。第一条是 Claude Code 的 Boris Cherny，五千九百多赞：「一年前我们发布了 Opus 4.5，第一个替我写了百分之百代码的模型。但发 PR 的速度没跟上，所以今天我们发布 Claude Ship 测试版。」他后面补了一句建议：先从一个仓库开始，Approvals 先用观察模式，等你信任它了再说。
小苇
这跟第一条是同一件事，但从做的人的角度讲。
大雨
对。第二条是 OpenAI 负责 Codex 和 ChatGPT 的 Thibault Sottiaux，四千二百多赞：「新版本推到你那里以后，你应该会感觉 ChatGPT 的回答质量明显提升。加上我们在简化 app、提速、把聊天和工作合并上的投入，到年底，日常使用体验会好很多。」
小苇
「把聊天和工作合并」，就是 OpenAI 这个月初说的，把 ChatGPT 的 Chat 和 Work 两个标签合成一个。
大雨
对。第三条是 Vercel 的 Guillermo Rauch，一千七百多赞：「我让 Fable 研究了我所有的编程对话，判断 Opus 和 Gemini Neon 哪个更好。可以理解成一个『个人评测』。它选了 Neon。谷歌回来了，这件事被讨论得太少了。」
小苇
「个人评测」这个说法，Dan Shipper 同一天也在讲，叫「个人 benchmark」。
大雨
对。做产品的人可以想一下：用户以后选模型，可能不看公开排行榜，而是看自己的数据。第四条是 Peter Yang，九十多赞，一条用户反馈：「ChatGPT Dots 还是感觉很多 bug，它没等我检查就把邮件发出去了，还会突然不回应。我很想喜欢这个产品，也许是我的提示词写得不对？」
小苇
「没等我检查就发出去了」，这正好是今天说的权限问题。
大雨
对。agent 能直接发邮件，是功能；不等你确认就发，对用户来说就是 bug。
大雨
播客是 Lenny's Podcast 十一月二十二号那一期，嘉宾是 Atlassian 的 AI 与产品负责人 Sherif Mansour。他在 Atlassian 干了十七年，是 Confluence 的第一个产品经理。
📎 来源: First principles: What it takes to be a great product manager in the AI era · Lenny's Podcast
小苇
讲了什么？
大雨
完整文字稿要付费，我只看到节目介绍。几个题目：产品经理的第一件事是建一个「共享大脑」，就是让团队对问题有同样的理解；三种产品经理，艺术家、科学家和总经理，怎么判断自己是哪种；为什么 AI 时代产品经理岗位增长最快；以及为什么 Atlassian 现在招的新人比以前任何时候都多。
小苇
多招新人，这跟很多人的预期相反。
大雨
对，节目介绍里的原话是「新人现在是你的秘密武器」。具体理由要听节目才知道。
结尾
小苇
今天的问题留给大家：你的产品里，有没有一个开关，其实管着两件用户想分开选的事？
大雨
我们下周三见。今天是十一月二十五号，这里是每日快报。
